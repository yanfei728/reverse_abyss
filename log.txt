零、先记住这条(2026-10-04 加;第六轮换成 json 时更新)
--------------------------------------------------------------------------------

**改游戏内容不用去动 levels/*.json。**

"能自己编辑关卡"是这个游戏的核心玩法之一 —— 一层关卡本来就是玩家/设计者
在编辑器里画出来的东西。所以:

  · 加一种地块、加一样地物(机关 / 道具 / 敌人)、调手感和数值、改界面……
    这些都是**引擎侧**的工作,做完**不要**顺手往 levels/*.json 的 asc 里塞示例、
    也不要为了展示新东西去改现成的关卡。留一条干净的地形,让设计者自己在编辑器里画;
  · 反过来,**加东西的时候要保证"编辑器里能画、画了就有用"**:
       - 地块看 js/level.js 的 TILE_IMAGES,实心/单向看 SOLID_CHARS / ONEWAY_CHARS;
       - 地物看 js/entities/*.js,注册(RA.register)完编辑器调色板**自动**就多一个笔刷,
         连图标都能用自己的 drawIcon 画;
       - 要"有碰撞体积"就实现 Entity.solidAt(r,c)(照 js/entities/ghost.js 抄);
       - **要带参数的东西别做字符** —— 写进关卡 json 的 objects[],类型和默认参数记在
         js/monsters.js(见第六轮那段。这类东西编辑器现在还画不了,下一轮接新格式时一起补);
       - 加完刷新 editor.html 确认:调色板里有它 / 能画上去 / 试玩时行为对,
         并且自检里有它的行为用例(合成一层测,不要依赖关卡池)。
    这就是"功能准确 + 能在编辑器里做"这两条,缺一不可;
  · 关卡的 json 里只留**数据 + 地图**:id(要和文件名一致)、difficulty、verified、size、
    sky、objects、asc。别的说明都别写进去 —— id 同时是文件名,显示也用 id
    (第六轮起**关卡名整个去掉了**,一层只有 id)。
  · 只有一种情况要动 levels/:关卡本身的**设计**有问题(比如某层爬不上去)。
    那时候是去改那一层的 asc 地图行(编辑器接上新格式之后就回编辑器里改),不是加功能。

一句话:功能进引擎 + 编辑器,关卡内容交给编辑器。改完记得跑
  node tools/test_all.mjs --fast
自检里那条"调色板必须自动多出新地物"的用例,就是专门守这条原则的。

关卡数据格式(第六轮换的,细节见文末"第六轮"那节):
  · 一层 = levels/<id>.json:地形和地物画在 asc 里(一行一项的字符串数组,所以地图照样
    一眼看懂、能手改;也接受一整段带换行的字符串),元信息写同一个 json 里;
  · 字段:id(要和文件名一致)/ difficulty(1~4 档,现在 12 层都是 1)/ verified(true/false,
    现在都是 true)/ size({"cols":N,"rows":N};和 asc 对不上会被提醒,以 asc 为准)/
    sky(0 = 随层数循环,1~8 = 固定)/ objects(带参数的元素,现在 12 层都是 [])/ asc;
  · **关卡的"名字"去掉了**:一层只有固定 id(floor01…floor12);引擎内部还留了一个
    entry.name,新格式里它就等于 id(为了让还没改的编辑器继续能用)。
    HUD / 塔结构表 / 提示显示的都是 id;
  · 旧的 levels/*.txt 已经删掉,模板换成 levels/_template.json;
  · levels.js 里内嵌的是 RA.LEVEL_DATA = {id: {…}};另有一份**兼容层**
    RA.LEVEL_TEXT = {id: asc 文本}(编辑器现在读的是它,下一轮编辑器接上新格式后可以删);
  · 引擎照样认老格式(纯地图文本、`// name:` 注释、编辑器导出的 txt、游戏里导入的 txt):
    RA.Level.fromText 还在;custom_<名字> 的自定义层显示成 <名字>(不带 custom_ 前缀)。
  体检 / 打包:node tools/sync_levels.mjs 扫 levels/*.json 并逐个体检(id 要和文件名一致、
  难度 1~4、verified 是布尔、size 与 asc 对得上、objects 是数组、sky 合法),有问题报错退出;
  levels/ 里若还留着老格式 txt,提醒一句(不算失败 —— 编辑器这轮写的还是它)。

                 变回来那一下格子里有人就再等一个周期

"一层关卡"在浏览器里可能有三把钥匙,理解这个才不会踩坑:
  ① levels/levels.js 内嵌副本 + http 下实时 fetch 到的 levels/<id>.json(没有 json 时
     退回老格式 levels/<id>.txt)                                → pack.pool
  ② localStorage['reverse_abyss.customLevels'] 的 custom_<关卡名>
     —— 游戏设置面板「导入关卡」这么存
  ③ localStorage['reverse_abyss.overrides'][<关卡 id>]
     —— 编辑器「保存到游戏」顺手记的"关卡内容"这一半
  把它们拼成"真正能用的关卡池"只有一处:RA.LevelPack.poolOf(pack)
  (游戏 Game.pool()、编辑器下拉框、自检都走它)。规则:
  · 同 id 只留一条;
  · 覆盖(③)如果对应一个池子里已有的 id → 换掉它的内容(改过的老关卡);
    但 entry.liveText 为真(http 下真读到了文件)时以文件为准;
  · 覆盖的 id 池子里没有 → 当成"只在浏览器里的新层"补进池子(标 overrideOnly);
  · 同一个**关卡名 / id** 落在两把钥匙里(① 和 ②/③ 都有) → 只留一条,
    后遇到的那份说了算 —— 否则塔结构表里会冒出两个同名的层。

实体碰撞(第三轮加的机制,写新机关要看):
  地形碰撞全在 Level._hitTiles() 一处。现在它除了查地形网格,还会问一遍
  Entity.solidAt(r,c):返回 true 的格子当成一块**实心砖**(横向挡人、能站、从下面顶头)。
  Level.solidEntityAt() / Level.blockedAt() 是给别处用的查询口。
  会变的机关只要按自己的状态返回 true/false,碰撞就跟着变。
  另一条"按类型生成实体"的路是 objects[](第六轮加的):实体类上写 Xxx.type = '...'
  再注册,关卡 json 的 objects[] 里那一条就会自动 new 出来(见 level.js 的 _buildObjects)。

贴图(第七轮把地块换成了贴图包里的图):
  · assets/tiles/ 那 5 张现在是 textures/block 那套 16×16 的像素画(直接拷进来的,
    不是 build_assets 生成的):grass_top ← grass_block_side / dirt ← dirt /
    brick ← bricks / stone ← stone / cloud ← snow;
  · **贴图尺寸和格子不一致也没关系**:画的时候统一缩放到一格(config.TS = 45px),
    规则只在 level.js 的 drawTile() 一处(游戏 + 编辑器都走它):
    像素画放大 → 关平滑(硬边);比一格还大 → 保留平滑再缩小;
  · 云板是薄平台:- 这一格只画贴图上面 29%(level.js 的 TILE_PLATE),下面留空,
    所以它看着还是"一条能穿过去的板子",不会变成整块砖;
  · assets/entities / sky / ui 还是 tools/build_assets.mjs 用代码画的;跑它**不会**

四、自检覆盖到哪儿(改代码时别把这些弄丢)
--------------------------------------------------------------------------------

引擎自检里有几条是专门盯"编辑器自定义关卡"这条链的:
  · 编辑器刚存的新层立刻进关卡池(不用刷新、不用重构),并标成 overrideOnly;
  · 改过的老关卡只换内容、不多出一层;
  · 同一个名字 / id 在两把钥匙里时池子里只留一层(同名去重);
  · 名字 / id 不同的两层都留着(不能为了去重吃掉别的层);
  · 塔结构表(tower.floors)里能真的抽出编辑器新存的层;
  · 关卡池里没有重复的 id。
引擎自检里"关卡数据 + 换格式"那一段(第六轮新增/改写的):
  · 关卡数据体检:levels.js 和 levels/*.json 逐个一致(改了忘同步会报)、levels.js 里没有
    已经删掉的关卡;每层数据的 id 和键一致 / difficulty 在 1~4 / verified 是布尔 /
    size 和 asc 读出来的大小对得上 / objects 是数组 / asc 是一行一项且行数等于 size.rows /
    asc 里没有注释残留 / **数据里没有名字字段**;
  · levels/ 里若还留着老格式 txt:只提醒一句,不算失败(编辑器这轮写的还是 txt);
  · 关卡数据怎么读:难度超范围夹回 1~4、写字符串也认、没写就是 1 档;verified 没写当验过;
    size 与 asc 对不上会提醒且**以 asc 为准**;objects 读进 level.objects、没登记的类型
    只留数据不报错、实体类上写了 type 再注册就真的生成实体;三种写法都认(json 对象 /
    JSON 字符串 / 老格式纯地图文本);
  · http 实时读关卡:会 fetch levels/<id>.json 盖过内嵌那份(尺寸 / verified 跟着变);
    那层没有 json 就退回读老格式 levels/<id>.txt;两种都没有时保留内嵌那份(不报错、不空池子);
  · 怪物参数表:js/monsters.js 装上了、表里有 fireball、它的参数先空着、没登记的类型返回 null;
  · 关卡切换的渐入渐出(climbFade 三档 alpha):刚开始旧层全亮 / 新层没出现 / 还没压暗;
    两层各在自己的镜头上且 panY 一直是 0(不再上下推整层);第一帧只画旧层;
    一半时旧层几乎淡没、新层还没亮、中间暗场最浓,且同一帧里两层都在淡;
    快结束时新层基本全亮;过渡结束站进新层、镜头偏移归零、透明度回到 1。
引擎自检里"会变的机关"那一段(合成的两层,不依赖关卡池):
  · x:在地形之外也算实心 / 往它走会被挡住 / 碰到就开始消失 / 消失后能穿过去 /
    散完 alive=false(同一局不再出现)/ 从下面顶上去也算碰到;
  · y:算实心 / 踩到的那一刻脚就在顶面上 / **踩到就消失**(不用站一会儿)/
    消失时不挡人 / 踩在上面的人会跟着掉下去 / 玩家离开后过一段会回来 /
    格子里有人时不重现(再等一个周期)/ 人走开后正常回来。
编辑器自检里:
  · 「打开选中的」拿到的是游戏正在用的那份(覆盖优先);

  · 导出的 txt 格式:第一行就是 `// name:`、注释头只有这一行(还是老格式);
  · **撞车这轮不拦**:新层起名 floor02 也能存,写出来的是 floor02.txt、
    levels/floor02.json 一点没动,池子里 floor02 还是只有一条(内容被这份覆盖);
  · 「← 回游戏」:没改过不问 / 有改动问一次 / 选是→存成之后离页 / 选否→不写文件也离页 /

2026-10-04(第六轮)· 关卡数据换成 asc+json、关卡切换渐入渐出、实体贴图 PNG 化、怪物参数表

做了什么
--------

1) 关卡数据格式换代:一层关卡 = 一个 levels/<id>.json(asc 打底 + json 元信息)。
   · 字段:id(固定身份,要和文件名一致)/ difficulty(1~4 档,现在 12 层都是 1)/
     verified(true / false,现在都是 true)/ size({"cols":N,"rows":N};和 asc 对不上会被
     提醒一句,以 asc 为准)/ sky(0 = 随层数循环,1~8 = 固定用那一张)/ objects(带参数的
     元素,现在都是 [])/ asc(地图本体,**一行一项的字符串数组** —— 所以地图在 json 里照样
     一眼看得懂、能手改;也接受一整段带换行的字符串)。
   · 12 个老 txt 全部转成 json,文件名就是 id:floor01…floor12
     (floor01–floor08 不动;北落 → floor09、新楼层_3 → floor10、浮石 → floor11、深界 → floor12)。
   · **关卡的"名字"整个去掉了**:一层只有固定 id;引擎内部还留着一个 entry.name,
     新格式里它就等于 id —— 纯粹是为了让还没改的编辑器继续能用。
     HUD / 塔结构表 / 提示显示的都是 id。
   · 旧的 levels/*.txt 删掉,模板换成 levels/_template.json。
   · tools/sync_levels.mjs 改成扫 levels/*.json,并逐个体检:id 要和文件名一致、难度 1~4、
     verified 是布尔、size 与 asc 对得上、objects 是数组、sky 合法 —— 有问题直接报错退出,
     不生成半成品。levels/ 里若还留着老格式 txt 会提醒一句(后半段改成"只提醒、不算失败",
     因为编辑器这轮写的本来就是 txt,那是预期内的)。
   · levels/levels.js 里内嵌的是 RA.LEVEL_DATA = {id: {…}};另有一份**兼容层**
     RA.LEVEL_TEXT = {id: asc 文本}(编辑器现在读的是它,下一轮编辑器接上新格式后可以删)。
   · tools/check_levels.mjs 默认扫 levels/*.json(老格式 txt 也认),报告里多打印
     id / 难度 / 已验证 / objects。
   · http 下的实时读取从"fetch txt"改成"fetch levels/<id>.json":能拿到就用磁盘上的
     实时内容(盖过内嵌那份);那一层没有 json 就退回读老格式 levels/<id>.txt;
     两种都没有时保留内嵌那份(不报错、不空池子)。
   · objects[] 这条新路:{"type": "fireball", "col": 3, "row": 5, "params": {}}。

   · 兼容:老格式(纯地图文本、`// name:` 注释、编辑器导出的 txt、游戏里导入的 txt)
     引擎仍然读得进来 —— 因为**这一轮按要求没有改编辑器**。所以 RA.Level.fromText 还在;
     custom_<名字> 的自定义层会显示成 <名字>(不带 custom_ 前缀)。

2) 关卡切换:渐入渐出(替掉原来的"整层上下推")。

   · 天空仍然是旧天空 → 新天空交叉淡化;过渡结束后新层从**它自己的镜头**开始
     (panY 一直是 0,不再上下推整层)。

   · 引擎:关卡数据体检(id / difficulty / verified / size / objects / asc、数据里没有名字字段、

   · 贴图:上面第 3 条那一整套。

为什么
------

· 为什么换格式:地图文本"一眼看得懂、能手改"这个好处必须留着,但一层关卡还得记住
  "它多难、验过没有、这层有没有火球"这类**带名字、带值**的东西 —— 塞进 `// name:` 那样的
  一行注释里不像话,也不该让引擎去猜。所以 asc 还是那堆字符(一行一项的数组),
  其余的摆进 json 字段:谁都能读、谁都能改,工具也能逐项体检。
· 为什么名字要去掉:名字同时当文件名、当关卡池 id、当塔里的显示名,三份东西一改名就打架
  (第三轮那套 fileNameOf / sameLevelName 归一化就是给这个擦屁股的)。改成固定 id 之后
  "身份"只有一份,文件名 = id,显示也用 id。
· 为什么关卡切换改成渐入渐出:原来是把整层上下推 —— 推的时候两层在屏幕里叠着、
  而且整屏都在动,看着晃。现在前一半旧层淡出、后一半新层淡入,中间压一层暗场,
  切到一半两层都淡、最黑,既能看出"上了一层",画面也不抖;两层的镜头本来就是各自独立的,
  所以过渡里 panY 一直是 0。
· 为什么把三张实体贴图挪进 assets:地块 / 天空 / 界面早就是 PNG 了,只有这三样还在代码里
  现画 —— 想换风格得改代码。挪过去之后"换风格 = 改 PNG"这一条对所有素材都成立;
  现画的兜底留着,所以删了图也不会崩。
· 为什么加 monsters.js 而不是直接写实体:怪物要带参数(速度、方向、血量),一个地图字符
  带不了。先把"有哪些怪物、各自有哪些参数、默认多少"定成一张数据表,行为以后再补 ——
  关卡里可以先写 objects,引擎补上行为的那一刻它就自动生效。
· 为什么编辑器这轮不改(以及顺带的后果):换格式这一轮先把引擎和内容做完,编辑器接新格式
  是独立的一块;只要引擎继续认老格式,编辑器就一天都不用停。代价写在"已知问题 6"里:
  它写的 txt 不进关卡源头、也不打包;"新层名字撞上内置关卡"那道拦截这轮失效(内置层没有
  名字了,它写的 floor02.txt 盖不掉 levels/floor02.json,只会往浏览器关卡池里写一条覆盖)。
  另外,自检里"levels/ 里没有老格式 txt 残留"那条也顺势改成"只提醒一句" ——
  编辑器这轮写的就是 txt,拿它当失败等于自检永远红。

  PASS 926,FAIL 2**(第六轮当时;第七轮换了地块贴图之后是 941 / 940);

遗留

· 编辑器还没接新格式(**已知问题 6**):它读写的仍是老格式 txt —— 引擎能读,但不进

  "新层名字撞上内置关卡"那道拦截这轮失效,下一轮要改成"按 id 拦撞车";

做了什么
--------

1) 5 张地块贴图换成 textures/block 里对应的像素画(原样拷贝,文件名不变):
     assets/tiles/grass_top.png ← grass_block_side.png   (草地:上面一条草、下面泥土)
     assets/tiles/dirt.png      ← dirt.png
     assets/tiles/brick.png     ← bricks.png
     assets/tiles/stone.png     ← stone.png
     assets/tiles/cloud.png     ← snow.png               (雪,当薄云板用)
   对应关系同时写在 js/assets.js 的 FILES 注释里,换图时照那一份对。
   (贴图包本身有 1000 多张方块,游戏目前只用到这 5 种地块;多出来的以后想加
   新地块时再挑,见"怎么扩展"。)

2) 尺寸问题(这一轮真正的代码改动):贴图是 16×16,一格是 45×45。
   · js/level.js 新增 drawTile(ctx, ch, img, x, y, size):把地块贴图**缩放到一格**再画。
     游戏(Level.draw)和编辑器(地图 + 调色板)都走这一条,两边不会长得不一样;
   · 缩放规则:源图比一格小(像素画)→ 放大时关掉 imageSmoothing,保持硬边,不然糊;
     源图比一格大(比如 128×128)→ 保留平滑再缩小,不会出摩尔纹;
     所以以后换成 32×32 / 64×64 的贴图包,只要替换 PNG,代码一行都不用改;
   · 云板是"薄平台",不能整块画(那会被当成实心砖):TILE_PLATE = { '-': 0.29 } ——
     只取贴图上面 29% 画在这一格的上沿,下面留空。`level.js` 一处定义,游戏和编辑器一起用。

3) tools/build_assets.mjs:**地块不再由它生成**(跑它不会把贴图包覆盖掉)。
   老那套"代码现画的地块"(45×45 带描边)没删,加了开关:
     node tools/build_assets.mjs --restore-tiles
   那是贴图包丢了 / 想回到以前风格时的后路。js/assets.js 里那 5 个 tileXxx() 兜底画法
   照旧留着,所以删了 PNG 也不会崩。

4) 自检补上"尺寸自适应"那一组(tools/test_assets.mjs):
   · 地块:在不在、是不是方形、**确实换成了贴图包里的图**(和 --restore-tiles 生成的不一样)、
     老地块还画得出来(45×45);
   · 用假贴图(16×16 / 128×128 / 45×45)各画一层楼:每种都铺满一格(45×45);
     16×16 时平滑是关的、128×128 时平滑是开的;
   · 云板只画上面一截(45×13,源图取上面 5 行,不是把整张拉扁);
   · 编辑器画地块走的是 RA.drawTile,而且 editor.js 里没有"按原尺寸画地块"的旧写法了。

为什么
------

· 为什么不把贴图先放大成 45×45 再存:放大是有损的(要么糊、要么像素格子不匀),
  而且下次换 32×32 / 64×64 的包就得重来一遍。放在**画的时候**缩,源图永远是原样的,
  换什么尺寸都直接能用。
· 为什么云板要特殊处理:云板是单向平台,旧贴图本身就是"上面一条、下面透明"。
  换成一块完整的雪方块之后,如果整块画出来,玩家会以为它是实心砖 → 直接撞墙。
  所以只画上面一截 —— 它看着还是"一条能穿过去的板子"。
· 为什么 build_assets 不再管地块:地块现在是别人的贴图(用户提供),脚本再生成一遍
  就等于把人家的图盖掉。改成"默认不碰,要旧样式加 --restore-tiles"。
· 为什么 16×16 放大到 45 会有点不匀:45 / 16 = 2.8125,不是整数倍,像素格子会 2~3 像素
  交替。要完全整齐得把 config.TS 改成 48(3 倍),但那会连带改手感 / 关卡尺寸 / 自检里的
  物理阈值,不是这一轮该做的事 —— 记在遗留里。
