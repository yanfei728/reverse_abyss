## 3. 数据与共享检查接口

沿用 schemaVersion 2 与完整 LevelData，以 ports.profile 区分接口契约；不是沿用 vertical-v1 的 col-only 几何。

```js
ports: {
  profile: 'cloud-pipe-v2',
  start:  { col: 2, row: 22 },   // 出口／本层起点
  finish: { col: 15, row: 7 }    // 入口／本层终点
}
```

宽 2、高 1、管内高 3、墙厚 1 集中在 config，编辑器/Codec/World 共享。宽高不在每个端点重复存储。缺接口的草稿仍可保存。

新版普通层的运行起始位置从 start 云板生成，`spawn:null` 合法；不要求作者另画 P，也不能用任意 P 绕过标准起点。旧 spawn 字段仍保真，大厅保留其独立出生点。共享起点计算返回 `{x, feet}`：角色中心对齐两格云板中心，feet 位于云板顶面；只在会话初始/重试生成玩家，跨层不得重置玩家或跳跃次数。

推荐共享接口（可按现有模块组织调整名称，不复制校验算法）：

```text
validateCloudPorts(data, {purpose}) -> Issue[]
getStartPose(data, playerSize) -> Result<{x,feet}> // 模板局部像素
buildLink(lower, upper, lowerOrigin, {kind}) -> Result<LinkGeometry>
// kind: 'stone-pipe' | 'lobby-direct'
LinkGeometry: {from,to,kind,innerRect,wallRects,commitY,upperOrigin}
```

`Issue` 沿用 code/path/message/severity，可附问题格子范围。新普通层在 decode/draft/play/publish、编辑器检查、开发/标准试玩、导入、正式抽选、Session 创建上调用同一套规则。play 前检查失败就留在编辑器，显示原因，不能先导航再黑屏。保存草稿不要求整关可通，接口合格不生成 certification。

vertical-v1 文件仍可读取/保存为待转换草稿，原 ports 保留；新版本运行/认证不再启用旧四格规则。需要作者明确重标云板或对唯一明确的候选执行转换预览后确认。不得用旧运行分支保留旧测试；历史测试改为旧格式保真和阻止错误运行的测试。未知 profile/字段继续保留并报告，不能静默改写。

## 4. 合规规则与编辑器

普通层必须恰好有一个 start 和 finish，start.row > finish.row；均是同一行相邻两块 tileId=5，选区必须是 2×1，并与一个完整两格云板段一致。重复标记同一端点幂等；已存在同类端点时明确替换，不累积多个隐形端点。

- finish 所在行为全图最高非空地形行，start 为最低非空地形行。两行之外允许空白格；不能放地形、活动对象或其路径。静态装饰是否越界按资源规则处理，不用装饰裁图。
- 每个端点左右一格必须在网格内，并是普通实心地形（1～4）；不要求它们已画成石头，也不重画作者相邻地块。连接器生成两端之间的石墙。
- 起点云板上方、终点云板下方，分别检查本层内 **宽 2、高 2 格**的局部进出净空；禁止实心地形、动态机关、伤害对象/路径占用。第三行允许作者的落脚平台：三张原图在终点下方第三行都有地块，不能为了沿用旧三行保护带而判错或删除它们。**三格管内净空是在两关之间生成，不是本关内三整行保护带**。外侧空间由管道生成，检查局部实际占用。
- 普通侧墙仍需封闭、连接外不得有可绕回旧层的旁路。用实际玩法包络及端点检查边界，不再要求最外层数组边缘是四格开口/三格安全带；不能因取消旧规则允许从任意顶边换层。

编辑器移除旧“入口 col/出口 col”字段，提供框选后“设为出口（起点）”“设为入口（终点）”“清除标记”，显示箭头/名称、错误格与石管预览。框选只写端点元信息，地形仍只有 terrain.tiles 一份真值。云板被擦除或改尺寸后原标记保留但显示失效，阻止试玩；撤销/重做恢复整份数据。扩图/平移同步 col、row；缩图的影响确认、备份容量、失败零变更继续适用。

## 5. 管道几何、碰撞与换层

以平台顶面为坐标基准，示意如下（# 是相邻墙/管壁，C 是作者云板，. 为净空）：

```text
#CC#  上层起点／出口云板
#..#  管内第 1 行
#..#  管内第 2 行
#..#  管内第 3 行
#CC#  下层终点／入口云板
```

两云板顶面相差 **4 格**，不是三格；TS=45 时为 180px。保留现有二段跳，需通过实际模拟和人工实玩验证能从下云板稳定到达上云板，不引入传送或为连接更改基础重力/跳跃。

对下层 A、上层 B，原点 Oa/Ob：

```text
Ob.x = Oa.x + (A.finish.col - B.start.col) * TS
Ob.y = Oa.y + (A.finish.row - B.start.row - 4) * TS
finishY = Oa.y + A.finish.row * TS
startY  = Ob.y + B.start.row * TS = finishY - 4*TS
innerRect = { x: Oa.x+A.finish.col*TS, y: startY+TS, w:2*TS, h:3*TS }
```

墙各宽 TS、高 3*TS，位于 innerRect 两侧。墙是 World 生成的只读静态碰撞/渲染几何，不写回任一模板；端点云板已有 terrain 所有者，不重复存储或生成第二块云板。楼层外侧空白边距保留，但不作为隐形边界或实心碰撞，允许空白包围盒重叠；实际玩法几何/管道不可重叠。计算原点需使用 row，不能依旧按 size.rows 拼接。

角色上穿终点云板时进入管道区域，**尚不激活上层**；脚底从下向上越过上层 start 顶面，且身体横向完全处于两格开口内，才提交一次 floorEntered。检测真实前后位置越线，不用碰头、按键或设 index 代替。上层 start 云板阻挡之后回落；管内仍受正常重力、跳跃、暂停和技能计时。

World 必须让玩家在管道与上层起点附近使用真实地形碰撞，不能由当前层顶边 clamp 把人压回、也不能在地图外造隐形整条底板。0→1 的 lobby-direct 不生成管壁，保留直接连续接入；适配两格 start 并指定共享云板单一碰撞所有者，不能复活旧四格接口分支。固定大厅/休整/Boss 创建新接口适配副本，保留旧文件。

下一层继续预热非攻击行为，越过 start 后才启用攻击与 activeTime。管道/起点交接区域无伤害；保持防回落、同一 Player、光环/CD 跨层和暂停冻结。上一层地形及其连接外观保留到再升一层才释放；生成连接的生命周期随下层实例/快照，不按出镜删除。
