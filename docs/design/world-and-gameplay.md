## 1. 可变尺寸与连接

每层使用局部格坐标：左上角 (0,0)，X 向右、Y 向下；瓦片尺寸 TS=45px。宽 cols、高 rows 可独立变化。入口在底边，出口在顶边；端口的 col 可变化。连接只平移，不缩放、不镜像、不旋转。

接口 v1 提案：开口宽 4 格；上下各 3 格安全带，开口与左右外墙至少隔 1 格。顶部出口和底部入口分别有净空，接口两侧实心封闭；完整侧墙封闭。安全带不能有自定义实心/动态机关、敌人、拾取物、传送门或穿过它的攻击与路径。梯板由连接器生成，单一所有者，不在上下两图各重复存一份。

“自由尺寸”允许不同宽度和高度，但合法模板仍须容纳接口与安全带。接口不匹配、出界、保护区重叠或墙体不封闭时可保存草稿，但不能发布；工具显示具体格子和原因。不得为了迁移旧图而自动裁剪或缩放旧图。

设下层 A 的世界原点为 Oa，出口左沿为 exitA.col，上层 B 入口左沿为 entryB.col：

```text
Ob.x = Oa.x + (exitA.col - entryB.col) * TS
Ob.y = Oa.y - B.rows * TS
接缝 Y = Oa.y = Ob.y + B.rows * TS
世界位置 = 楼层原点 + 局部位置
```

例如 A 出口 col=6，B 入口 col=2，则 B 向右平移 180px。B 的对象、路径、背景都使用同一个原点，不分别补偏移。塔可能向左右延伸，世界坐标允许负数。

接缝开口外不留旁路：上下层不同宽度产生的台阶边缘由各自封闭侧墙及顶/底边界处理，不能只铺一小段梯板却允许从两侧绕回旧层。此约束也适用于大厅、休整和 Boss 的连接。

## 2. 跨层提交

玩家从下向上穿过梯板。仅当玩家脚底由接缝下方到达上方，且碰撞盒横向完全在开口内，才提交 `floorEntered`。头部进入、贴边擦过都不提交。实现使用前后位置的越线检测，避免高速移动漏判。

提交一次后：

1. 更新当前楼层索引，记录本局首次到达；不重建玩家，不改速度、跳跃次数、生命、光环或冷却。
2. 原当前层变成上一层静态地形快照；清除其敌人、攻击与未领取物。后续追捕者按单独规则迁移。
3. 新当前层保留预热后的移动位置；从零开始攻击/索敌/超时计时，不补发预热期间“欠下的攻击”。
4. 激活后的下一模拟步才处理新层攻击；保护区仍无伤害。
5. 加载新的下一层，释放原 n−1 层快照；同一个边界不能重复触发奖励或回复。

入层后梯板阻止回落；首版没有主动向下穿板操作。下落到接口附近仍可看见上一层，但玩家始终属于当前层。

## 3. 三层生命周期

玩家当前位于 n 层时：

| 范围 | 保留内容 | 逐步运行 | 伤害/攻击 |
|---|---|---|---|
| n−1：上一层 | 地形快照、塔内背景与静态装饰；门/浮石退出时状态 | 不运行 | 全部关闭 |
| n：当前层 | 地形、对象、敌人、拾取物、本层计时 | 完整运行 | 正常，受安全区/暂停约束 |
| n+1：下一层 | 地形、素材、对象、敌人 | 巡逻、路径与无攻击动画提前运行 | 禁止索敌、攻击、接触伤害、机关触发；超时为零 |
| n−2 及更早 / n+2 及更晚 | 仅塔清单及必要轻量记录 | 不运行 | 无 |

例：在 2 层可多次上下跳，1 层地形一直保留；进入 3 层后释放 1 层，保留 2 层地形。不能用“刚离开摄像机”作为释放条件。

下一层齿轮等路径对象运动，但不能伤人；玩家光环也不能跨层提前击杀。地刺攻击、浮石踩踏等需要玩家激活的行为不因预热自行触发。下一层移动相位取决于此前停留时间，所以重温首先承诺模板内容与排列，不承诺敌人逐帧位置。

旧层动态地形只保存显示快照，不保留它的模拟对象；旧层无伤害、无拾取、无重新激活。共享贴图可继续缓存在素材管理器中，“释放楼层实例”不要求每层重新解码相同图片。

未来跨层追捕：实体使用实例 ID，转交后不能在两个列表重复更新；迁移计数最多 1；进入大厅/休整/Boss 清除追捕及其伤害体。v0.1 不实现追捕 AI，只不破坏此边界。

## 4. 镜头与会话

镜头保持跟随与垂直死区思想，但从单层边界改为连接区域，跨层不 `snapTo` 新玩家。宽窄层切换采用平滑约束，不把整个塔历史包围盒当作当前镜头限制。验收包含偏置接口、窄接宽、宽接窄、不同层高和反复接近下接缝；不能用淡出遮盖位置跳变。

`GameSession` 只保留一套模拟顺序：消费动作边沿 → 无攻击运动/机关状态 → 玩家运动与碰撞 → 跨层提交 → 当前层攻击与技能伤害 → 伤害/死亡/Boss 结算 → 事件输出。移动/伤害顺序在测试中固定，不允许试玩另写一套。

角色死亡与 Boss 阶段转换具有结算锁。玩家本步死亡时不提交试玩通过/胜利；同一时刻击败 Boss 且玩家死亡按失败处理（技术提案）。发布回执必须由会话结果产生，不能由页面按钮直接设置。

模拟按 1/60 秒推进；输入按住状态可重复读，pressed 边沿只在一个模拟步消费。暂停、失焦、后台时不推进预热、攻击、超时、光环或冷却，恢复前清除按住输入与累积时间，避免追算后台时间。

## 5. 光环、伤害与死亡

已确认：没有普通攻击；光环持续 14 秒，冷却从施放起计算 20 秒；开局可用；跨层保留；普通敌人被击杀后光环继续；命中可受伤 Boss 后光环消失且冷却不重置。

验收时间线（模拟时间）：

```text
t=0：施放，active=14，cooldown=20
t=14：自然结束，cooldown=6
t=20：可以再次施放
若 t=5 命中 Boss：光环立即结束，仍需等到 t=20
若中间暂停 30 秒：恢复时两个剩余时间不变
```

每次施法分配独立 castId。伤害判断使用视觉一致的范围；普通敌人通常一次命中死亡，机械地刺/齿轮不受技能伤害。护盾 Boss 不受伤，光环不会因碰盾自动消失。

初始建议：光环半径 1.5 格；玩家 100 血、普通伤害 20、受伤无敌 1 秒。多个伤害源同一步只结算一次；稳定按伤害优先级及对象实例 ID 选中，不依数组遍历偶然顺序。无敌反馈必须可见，不显示伤害数字。

死亡后清除光环、敌人和本局拾取/休整记录，生命与技能恢复开局状态，回到大厅。推荐保留原塔清单供重试，手动重构才改变排列。不要沿用旧程序坠落后无伤回本层起点作为正式死亡规则；越界细则待 T07 确认。

## 6. Boss 与休整

首版 Boss 两生命阶段：

```text
shielded（带盾、预警并攻击）
  → exposed（停攻、清除 Boss 所有伤害体、移动到可接触位置）
  → resolving（首次有效光环命中；锁定阶段；清除该 castId 的全部召唤物）
  → shielded（还有生命阶段） / defeated（没有阶段）
```

exposed 没有超时，不继续攻击。需同时取消攻击定时器、待发事件、激光、弹幕、小火球、接触伤害及其他 Boss 所属伤害体，不能下一帧再次生成；纯视觉残影可保留但不得仍可伤人。玩家光环在进入 exposed 时不清除，只有有效命中才清除。

首版 Boss 场地不放独立的地刺/齿轮等有害机关，外来追捕也不得进入；exposed 必须确保场内全部敌对伤害源关闭，不能以“这个伤害物不归 Boss”保留暴露阶段伤害。

一次有效命中仅消耗一个生命阶段。同一步多段重叠或多个召唤物不能穿过 resolving 连续打掉两阶段。重生后是新的带盾阶段，不补发旧攻击。

场地必须让基础移动能力和近身光环碰到 exposed Boss；不能要求随机遗物。首版预警与三种攻击使用简单图形也可，但安全区、判定区域和可接触高度要可读。护盾阶段初始建议 12 秒，其余数值由 T07 给出并实际试玩。

休整不生成敌人/超时。建议首次进入回复 40，封顶 100；按 floorInstanceId 记录领取，暂停、靠近接口或重新渲染不会重复回复。固定层的出口条件由场景控制：Boss 未击败出口不开；胜利仅在最终 Boss defeat 后产生。

## 7. 试玩与发布

编辑器送出不可变模板快照，正式游戏和试玩都由同一 GameSession 驱动。单图试玩包含标准入口支撑和出口接缝，按真实跨线规则判通关，不能保留旧“碰到任意 G 就赢”。

标准认证配置提案：满血、无遗物、初始技能剩余冷却 20 秒、初始无活动召唤物、正式基础移动、不使用辅助作弊，下一层预热相位从零。冷却结束后可正常施法，仍遵循 14/20 秒、跨层保留与暂停冻结；不是永久禁用技能。调试可用满技能或无敌，但只能产生 debug 结果，不能发布认证。模板必须自行可通，不依赖上层模板提供额外平台。

通关只说明该内容在记录的标准条件下存在成功路线，不证明所有玩家、低血状态或所有预热相位都可通。移动对象另测多种预热时间；发布检查也不替代相邻地图拼接检查。

回执绑定 sessionId、草稿快照 hash、rulesVersion、rulesFingerprint、profileId 与 passed 结果。测试期间改图、旧窗口晚回传、死亡后按钮误触均不能认证新草稿。任何内容变化都失效；保存/导出不要求通关，发布才要求通关。
