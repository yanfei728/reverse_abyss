## 3. 固定场景数据

沿用 schemaVersion=2、terrain 单一真值。普通图不重新开放出生点、终点或 Boss 自由摆放工具。建议使用现有会参与内容 hash 的 `extensions.fixedScene` 存放程序维护锚点，不新增第二份地形格式：

```js
// level0 运行副本
kind: 'lobby', ports: null, spawn: null,
extensions: {
  // 保留作者原 extensions；以下是程序新增的已知字段
  fixedScene: {
    profile: 'short-fixed-v1',
    playerSpawn: { centerCol: 10, feetRow: 20 }
  }
}

// Boss 运行副本
kind: 'boss', spawn: null,
ports: { profile: 'cloud-pipe-v2', start: { col: 1, row: 20 }, finish: null },
extensions: {
  fixedScene: {
    profile: 'short-fixed-v1',
    boss: { centerCol: 10.5, centerRow: 14.5 }
  }
}
```

休整运行副本不需要另造出生或Boss锚点：`kind:'rest'`、`spawn:null`、`ports:{profile:'cloud-pipe-v2',start:{col:13,row:18},finish:{col:1,row:8}}`。用已有入层事件执行一次回血，不在中间云板/停留时间上触发回复。

上述锚点以**网格线坐标**表示中心或脚底，不是格子索引，不再另加0.5。出生是两个 x 标记覆盖区域的中心，横坐标10格，不是整张21列地图的中心10.5格。TS=45、角色20×36时：大厅局部 x=440、feet=900；Boss 99×99时局部左上约(423,603)，中心(472.5,652.5)。运行时根据真实角色/Boss尺寸计算，不能另写位置常量。

固定锚点共享校验：有限数、在场景内、出生不嵌实心、脚底有支撑、Boss碰撞盒在室内且不与实心相交。这个 Boss 位置由用户本轮明确确认。没有锚点或内容非法应给出明确错误，不悄悄沿用“数组顶部+2.5格”的旧位置；那会把 Boss 放在作者房间外。Boss 攻击覆盖范围取房间实际活动区域，不能以顶部空白为房间地板或天花板。

未知 fixedScene profile/参数按已有保真规则保存草稿、阻止运行；只对已知字段做共享检查。若实现方选择等价字段命名，需在本卡范围内同步契约、编码/校验/生成器/测试，不能在页面另存一份坐标。

端点要求按 kind 和用途区分：

|---|---|---|---|
| normal / rest | 必须 | 必须 | 继续执行现有两格云板、支撑、净空与相对高度规则 |
| 此固定 lobby | 无 | 无 | 使用 playerSpawn 与 F 交互；不调用管道连接器 |

## 4. 大厅交互与会话接口

建议最小接口如下，名称可适配现有模块，但核心逻辑在 World/GameSession，页面只转输入和显示：

```text
getFixedSpawn(data, playerSize) -> Result<{x, feet}>          // 局部像素
getBossPose(data, bossSize) -> Result<{x,y}>                 // 局部像素
GameSession.interactionPrompt() -> null | {kind:'start-tower', text, action:'interact'}
GameSession.pressInteract() -> 请求一个按下沿；现有方法可复用
World.enterFirstFloor(player) -> Result<floorEntered>       // 仅合法 lobby→1
```

F 对应已有语义动作 interact；短塔的提示与键盘改为 F，编辑器的 F 填充不受影响。旧 E 不再作为短塔唯一交互键；是否保留别名可由实现方统一处理并写清操作。

出生就能看到轻量对话提示“按 F 开始挑战”，不新增剧情/NPC/确认流程。建议作用范围为出生锚点周围1.5格、置于 config；离开范围隐藏，返回恢复。提示不是暂停窗口，按一次 F 直接进入第1层。失焦/暂停/死亡/菜单清理按键来源；按住F、键盘repeat、连续按F均不能跳过多层。

大厅→第1层：复用同一 Player 和本局清单，允许这一次显式设置到第1层 start pose，清速度/跳跃缓冲等瞬时移动状态，不重置生命/光环/CD，不重抽塔、不生成认证。相机当帧对准第1层，不能让玩家镜头追过空白。其余入层仍只由真实运动触发，不重建或传送玩家。

World 对0→1生成 `kind:'lobby-transfer'` 的逻辑记录（或等价显式 transition），**不生成 stone-pipe / lobby-direct 物理几何**。lobby 与爬塔区域独立布局/独立参与渲染和碰撞，不能重叠碰撞，也不应同时出现在同一镜头；第1层之后原点继续按云板公式计算。不要在 World 里对 floors[0].ports.finish 盲取值。

第1层可预加载但 F 前不攻击、activeTime为0；F提交一次入层。普通层/休整/Boss预热和计时规则继续保留。入 Boss start 后仅创建一次 Boss，随后等待两阶段打完；exposed 停攻清场和单次施法单阶段仍必须成立。

## 5. 石管：复用已有石块、统一实际几何

管内仍宽2、高3，左右各1格墙，两端云板顶面差4格。**石墙是已有 tileId=4、字符“=”、资源 tiles/stone（assets/tiles/stone.png）的逐格地形效果**。通过共用瓦片绘制方法画六个石块；不能画另造灰矩形、整块拉伸纹理、添加新石头资产或新瓦片类型。正常资源缺失时沿用资产系统现有兜底。

生成器只派生连接区域，不改写作者模板。建议把LinkGeometry六个格子表达为世界格坐标+tileId=4，或让两条墙矩形与瓦片视图共享同一真值。短塔碰撞/绘制必须从**同一连接几何**派生；保留供以后试玩复用的接口，本轮不要求修改开发/标准试玩页面。

生成的四条物理连接：test1→test2、test2→test3、test3→休整、休整→Boss；每条2列×3行净空、左右6块石头齐全，端点接缝无缺口。原作者云板只保留原地形所有权。

## 6. 碰撞修复的边界

目前 FloorView.move 只委托当前层 Level.move；管壁部分位于负行，又被 Level._hitTiles 限在原数组内。下一层虽已显示，墙体还没参与查询；同时 FloorView 仍以原数组外框执行旧顶边/底边 clamp。这些是已复现的穿墙原因，不能简单把所有云板改为实心解决。

在保留现有物理积分/手感的前提下，让给 Player 的**世界碰撞适配器**使用统一的真实静态几何：当前层地形、连接墙体，以及上层起点附近已显示的地形。需要的前一层快照地形保持到下一次上升。preview 的地形可碰撞，不代表它的怪物可以提前攻击。

`move / blockedAt / standingOn`（包括落脚容错）应使用同一世界查询域和坐标转换。不能只修一种查询，不能简单对整张未裁空白数组补实心；旧顶边/底边/四格开口 clamp 不再决定新云板场景的物理边界。左右/顶部封闭由实际作者石墙及连接器决定；异常掉出已有死亡处理保留。

- 石块四向阻挡；云板保留单向：从下往上可穿，从上落下可站，横向云板本身不当墙。
- 同一动作不能顺带穿过相邻实心石块；云板与墙的边界需要斜跳、贴边、顶头检查。
- 正常跨层只在脚底从下向上越过上层 start 顶面且整个身体横向在2格内提交；只露头、碰墙、擦边不提交；回落不重触发。
- 入层后起点云板防回落；不能在数组底部造整片隐形底板。上一层快照、管壁外观/碰撞一同保留至再升一层，之后一同释放。
- 不对所有全塔层地形永久启用碰撞/渲染；控制在当前/预热/快照及关联连接内。
