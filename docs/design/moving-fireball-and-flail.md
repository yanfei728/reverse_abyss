2026-11-09，**27/B4-R11怪物主体工程与用户试玩通过，返回原稿问题由28修复**。N04/N05已复验关闭，现有运动/碰撞/伤害/光环目标保持；见 [验收](../checks/review-B4R11-2026-11-09.md) 及 [28设计](trial-return-soul-and-sewage.md)。

## 1. 已确认行为

设正常移速`V = C.MAX_VX`，当前340像素/秒；一格`TS = C.TS`，当前45像素。使用正常地面最大移速这个固定基准，不随玩家当前速度、加速/松手、空中上限300、朝向或所在平台变化。所有数值/比例集中config，共用运动解析读取。

| 类型 | 运动和速度 | 编辑器 | 正式游戏与独立试玩 | 光环 |
|---|---|---|---|---|
| gear 齿轮 | 沿原90度路线，固定V=340px/s | 原连续左键节点、右键完成；路线可见 | **显示轨道**，单点静止、往返/闭合保持 | 不可消灭 |
| fireball_moving 移动火球 | 与齿轮相同路线/运动方式，固定V/2=170px/s | 完全复用齿轮的放置/路径手势，编辑时显示路径 | **不显示路径/轨道**，只有移动火球本体 | 可消灭 |
| flail 流星锤 | 固定端点为圆心，轨道半径4格；锤头线速度2V/3 | **一次点击放端点即可**，不画路线/填写坐标参数 | 显示端点、端点到锤头的锁链、锤头；不画整条圆形辅助线 | 不可消灭 |

用户明确：齿轮速度覆盖全部已有齿轮，不只改变新对象默认值；作者尚未绘制新关卡，不据此删旧数据。移动火球可被光环消灭；流星锤、齿轮、地刺不可消灭。**所有怪物都没有实体阻挡，仍有伤害判定；流星锤仅锤头伤害，端点/锁链无伤害无阻挡。** 静止火球保留可消灭/无实体阻挡。门/浮石/弹簧是已有地形机关，不因本次“怪物无阻挡”取消其本来行为；真实terrain1–4石块等仍阻挡。

移动火球与齿轮相同的是路径、无重力、穿过地形而不受墙/云板反弹、接触伤害和生命周期；光环可消灭是用户明确的区别。单点路径允许静止，不能为了“移动”强迫两节点。闭合仍是90度折线闭合，不变为圆/平滑曲线。

## 2. 流星锤的单位与默认姿态

用户已确认“转速2/3移速”指**锤头沿圆周的线速度**：

```text
orbitRadius = 4 * TS = 180 px       // 圆心到锤头中心，不是锤头大小
headSpeed = V * 2 / 3 = 226.666… px/s
omega = headSpeed / orbitRadius = 34/27 rad/s
period = 2π / omega = 27π/17 ≈ 4.9896 s/圈
```

实现默认（非用户逐项指定）：端点在所点格中心；初始锤头位于端点正下方，顺时针匀速360度旋转。用屏幕坐标`x = anchorX + R*cos(theta), y = anchorY + R*sin(theta)`、初始theta=π/2、theta递增。不是左右摆动，不做绳索/重力/反弹模拟，不受地形挡住。锤头判定半径先沿用齿轮默认0.5格，伤害默认20，集中注册表；**轨道4格不能误用成锤头半径4格**。

创建时即求出正确初始头位置，不能先画/判伤害于端点、首帧才跳到圆周。端点挂在石块上时，放置不可擦掉该格terrain；锤本身不阻挡，但原石块仍阻挡。锤头/锁链可能经过地形或超出作者地形边缘，保持正常运动；不裁回地图、不改半径，不把圆周净空变为发布合规门槛。

## 3. 显示与碰撞分离

正式和试玩共用`RA.drawFloorObject`及必要的小绘制辅助，不能只改一个入口。齿轮轨道取该实存实例的路径数据，绘制普通细轨道，不带编辑器节点/坐标/箭头/选框，不参与伤害/solid；往返画开放折线，loop含闭合边，单点可仅有支点。共用pathId可去重画轨道，不能因此合并对象运动相位。snapshot旧层只保留地形，不保留怪物/轨道/链条；不遍历全塔模板画未加载对象，不能重现26号的幽灵几何问题。

移动火球编辑时路径可见，正式/试玩不画路径；消灭后不再显示、伤害或在本局恢复。流星锤链条为端点到当前锤头的线段/链节，随角度和相机更新，保持连接，不做链条伤害。正式/试玩只显示链条，不显示完整圆周范围；编辑器悬停/已放置对象可显示4格辅助圆及初始链条帮助作者作图，辅助圆不成为另一份路径真值。

怪物无实体阻挡必须覆盖move、standingOn、blockedAt/落脚辅助和相关solid查询，不是只去掉画面边框。尤其当前`FloorInstance.solidAt`把地刺整格当实心，**本卡明确取消**。地刺仅在伸出阶段，用角色身体与**实际伸出的尖刺区域**重叠造成伤害；预警/回收无伤害，底座仅显示。伤害区域从共用绘制几何/常量派生，不能去掉底座后还只用旧`feetOnTop`导致走进尖刺却不扣血，也不能把底座/整格永久变成伤害体。

所有接触伤害继续共用每步一次伤害/无敌时间/死亡规则。不重新实现角色碰撞，不取消真实地形、门/浮石/弹簧等机关碰撞。

## 4. 数据与模块契约

保留schema2和唯一terrain真值；新增两类进`EntityRegistry`，默认/范围进config，所有读取/试玩/发布共用已有`purpose:'load'`能力检查。稳定type采用`fireball_moving`、`flail`，不要混用旧原型的`fireball`名或替换`fireball_static`。

```json
{
  "id": "moving_fireball_1", "type": "fireball_moving",
  "col": 5, "row": 8,
  "params": {"radiusTiles": 0.5, "damage": 20},
  "pathId": "path_1"
}
```

```json
{
  "id": "flail_1", "type": "flail",
  "col": 10, "row": 8,
  "params": {"radiusTiles": 0.5, "damage": 20},
  "pathId": null
}
```

`fireball_moving`必须引用现有PathData，初始col/row与首点一致；`flail`的col/row是端点，`pathId=null`，圆周由固定规则派生。这里radiusTiles表示锤头/火球本体判定半径，不是流星锤轨道半径。不得把头当前位置、theta、路径距离、alive写回对象模板。

齿轮旧`speedTilesPerSecond`字段继续可读取/原样保存，不能因弃用而报未知参数或重算所有作者hash；**本轮起gear实际速度统一取V，旧字段不再覆盖**。新放齿轮若仍保存该兼容字段，默认显示/写入值与V/TS一致，不继续写2却宣称是实际速度。移动火球/流星锤本轮不提供任意速度、半径、方向表单，固定规则在config/规则中记录，不扩回原27参数卡。导入已支持的半径/伤害参数仍保真。

建议最小共用边界（命名可等价调整）：

```text
MotionRules.speedPx(type) -> V / V/2 / 2V/3
ObjectMotion.sample(object, path, motionState, dt) -> {rx, ry, nextState}
MonsterTraits.haloDestroyable(type) -> boolean
FloorInstance.updateAmbient / updateActiveObjects / drawFloorObject
```

可以用现有World/FloorInstance内的小辅助实现，不要求新框架或通用AI系统。齿轮/移动火球共用一份距离采样、反射/闭合算法；流星锤是同一运动更新入口的圆周分支。渲染不能推进模拟，速度不按帧数累加，不调用角色的实体阻挡处理去移动怪物。

正式GameSession和独立TrialSession当前各有只识别静止火球的光环分支；改用同一可消灭类型判定，加入移动火球，机械类始终不消灭。伤害同样按实际rx/ry换到世界/玩家一致坐标，不能在端点或原始路径首点判移动后的头。

## 5. 编辑器与存储

将原齿轮手势最小泛化为可接收对象类型的路径手势，齿轮/移动火球复用：选元素→左键首点/连续节点（自动直角折线预览）→右键完成；默认往返，可选闭合，单点静止，Esc回滚整个本次创建/dirty/撤销，完成/取消消耗按压。新类型有各自清楚图标/名称/提示，不能用同一`~gear`硬编码放错type。原齿轮行为不退化。

流星锤：选工具→鼠标悬停预览端点/圆周范围→单击提交一个端点对象，一次撤销；不进入路径模式、不要求第二点/半径输入。撤销/重做、JSON/草稿、扩大画布/平移/裁外侧空白均保留对象身份与端点。坐标偏移只对对象锚点/路径点统一加减，头位置自动重算，不多存一份头坐标。

裁空白/内容包络考虑移动火球原路径与流星锤4格圆周扫掠（含头范围）；沿用只在原地图内裁剪/统一偏移的约定，不擅自扩张地图。圆周超出原图不成为运行/发布拒绝条件，不夹角、不删除怪物；不为本卡重做整套裁剪。作者不点裁剪时原尺寸/空白不动。

不清池、不改原示例图/发布记录/草稿；用户尚未开始正式新图创作，也不能假定旧资料全无齿轮后删兼容。只读固定大厅/休息/Boss保持。新图试玩通过后才显式发布，四档/test3补位和当局不可变清单保持。旧客户端不识别新类型时保留草稿并明确报不支持，不能静默删除后发布。
