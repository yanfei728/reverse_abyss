# 普通关卡编辑器：工具补齐、尺寸与双主题工作台

最近更新：2026-11-08。**用户已开始编辑器批次，当前执行19号卡**。端点鼠标标记/自动坐标、直角齿轮与裁剪的最新规则见 [鼠标工作流](editor-mouse-workflow.md)、[19号卡](../tasks/19-editor-markers-and-gear-paths.md)，覆盖本页旧手填端点/路径方式；R3试玩与R4裁剪重新纳入。已有现代双主题工作台保留，不从头重写；固定场景只读，不加其他怪物/APK。18号卡碰撞已验收，仅回归。

## 1. 用户决定与边界

- 普通关卡编辑器移除旧 P 出生点、旧 G 终点工具/说明；起点与终点由两格云板端点承担。删除的是旧操作入口，不是删除历史文件中的信息。
- 用户明确：**Boss 层与初始大厅特殊，不应该自由编辑**。本轮不增加 Boss 摆放、Boss 参数面板、场景类型切换或大厅编辑。休整仍沿用已有固定场景管理。
- 本轮补齐**已经在当前短塔运行的内容**，不引入新怪物/攻击 AI：火球可放置，地刺/路径齿轮及弹簧/门/浮石工具同时补齐；Boss 仍由固定场景创建。
- 修清关卡尺寸、视图尺寸与导出尺寸的关系，并能明确裁去不需要的外侧空白；不在普通导出时悄悄裁图。
- 界面改为现代极简、扁平、卡片式工具工作台；提供浅色、深色模式。只改 PC 编辑器，隐藏摇杆、游戏美术/音效、Boss 重设不纳入。

固定场景如果被打开，显示只读预览和“内置固定场景”提示；禁用画图、元信息修改、尺寸/裁剪、对象编辑、标准认证发布。允许查看与导出原数据备份，不偷偷转成普通关卡或删除 Boss/出生信息；新建/打开普通层可继续编辑。底层 handler 也检查只读状态，不能只灰掉按钮却仍被快捷键修改。开发 agent 为新接口必要适配固定场景副本，属于程序维护，不等于开放编辑器功能。

## 2. 当前代码核对结论

见 [核对脚本](../checks/editor-scope-2026-11-07.mjs)、[结果](../checks/editor-scope-2026-11-07.json)。

- `EditorPalette.build()` 会过滤没有旧字符 letter 的注册对象，导致火球/地刺/齿轮不在左侧画笔中；右侧参数表已能添加这些类型，不能误写成完全没有数据/运行能力。
- 当前 G 工具已废弃，P 仍在；新云板端点工具尚未完成。需要在15/16号卡整体清理旧入口和文案，不能只删 P 后继续要求普通层提供 spawn。
- `exportJSON()` 直接编码 EditorModel。实际调用 resize/fitView/zoom 后，20×20 模型仍导出20×20、内容 hash 不变；调用越界扩展 ensure(29,29) 后模型才变成30×30并导出30×30。当前默认勾选“画到界外自动扩展”，这是需要排查的路径；尚未重现用户原页面上的具体操作，不能确证其30×30由哪一次操作造成。
- Boss 是 GameSession 进入固定 Boss 层后创建的独立控制器；按用户决定继续保持，不为了统一调色板把它变成普通 objects。

## 3. 统一对象摆放

左侧分类：**地形／机关／怪物**。普通对象从 EntityRegistry 的稳定 type 与参数描述生成，不再要求 letter；letter 只用于兼容旧文件/旧图标。

| 分类 | 本轮可直接选择并点图放置 |
|---|---|
| 地形 | 草、土、砖、石、云板等已有静态地块；橡皮为空 |
| 机关 | 弹簧、门方块、浮石、地刺、路径齿轮 |
| 怪物 | 当前短塔已经实现的静止火球 |

选择状态建议为 `{mode:'tile',tileId}` / `{mode:'object',type}` / `{mode:'port',role:'start'|'finish'}`，不用虚构 P/G/字母把所有对象塞入字符地图。对象仍写 objects、参数/路径仍走共享描述，实际运行使用同一 Session。显示图标、中文名称与简短行为；修正注册表中已经实现却仍标注“未实现”的陈旧能力说明。

点击已有对象可选中，右侧显示参数、坐标、关联路径及删除；新增/修改/拖动/删除能撤销。长按刷过同格同类保持幂等，不无限生成重复对象；齿轮路径缺失允许留草稿，但明确阻止试玩/发布并指向路径工具。未知对象仍保真显示占位与问题，不加入可放置菜单或改成已知怪物。

## 4. 尺寸的唯一真值

只保留 `LevelData.size + terrain.tiles` 为实际关卡大小。视口像素、缩放、相机平移属于 EditorView，不写回 LevelData：

```text
地图尺寸 = 实际网格，保存/导出/运行使用它
内容占用 = 当前地形、对象与空间引用的包围范围，供裁剪预览
视图范围 = 屏幕当前看得到的区域，可大于/小于地图
```

- 明确画出实际地图边框，内部才画关卡网格；外部压暗/使用不同中性色并标“关卡外”，不把屏外/画布填充画成另一圈可编辑地图。
- 顶栏或状态栏始终显示“地图20×20”；尺寸卡可显示“内容占用…”，两者不混称。输入框采用“宽／高＋应用尺寸”，未应用值不假装已改模型。
- 自动扩展默认关闭、可显式启用；关闭时越界绘制不改数据并提示边界。开启时一笔操作内按需扩展，立即显示旧→新尺寸、可整笔撤销；擦除地图外空白不应扩大地图。平移、适应窗口、缩放、切主题、面板开关绝不扩图。
- 普通导出、复制、查看 JSON、草稿保存全部基于同一模型快照；模型20×20即导出20×20，模型30×30时如实显示/导出30×30。不能仅在下载代码中砍成20×20，让模型、草稿、文件互不相同。

### 4.1 显式“裁去外侧空白”

提供按钮，先显示裁剪预览：原尺寸→新尺寸、四边移除行列、活动坐标偏移、认证会失效等实际影响，再确认应用；取消零变更，确认后一次撤销可完整恢复。默认裁掉不必要外边距，保留必要接口净空/支撑；内部空洞、作者主动保留的空间只有其明确确认后才改变，不按每一行分别缩短。

内容范围不只看非零地形：包括云板端点及必须保留区域、所有已知对象实际范围、路径全段/对象运动半径、装饰的可解析范围，以及仍需保真的活动出生信息。未知对象/未知空间语义无法安全计算时，拒绝自动裁剪并说明，不猜边界、删字段或裁掉肉眼看不到的对象。空关卡不产生0×0文件；无可裁内容时保持原尺寸。

向左/上裁剪需统一平移 terrain、objects、paths、ports.start/finish 的 col/row、可解析装饰及活动兼容字段；历史 retiredPorts 等带原尺寸的备份保持原历史坐标，不拿历史备份当活动内容，也不破坏其保真。规则校验和容量检查在候选副本上完成后才提交，沿用既有失败保护。

建议复用 EditorModel，增加小型纯方法，不新建第二套文件格式或画布真值：

```text
contentBounds() -> Result<{occupiedRect,safeRect,issues}>
cropCandidate(rect) -> Result<CropPlan>
CropPlan: {beforeHash,beforeSize,afterSize,offset:{col,row},data,impact}
Editor.applyCrop(plan) -> Result<{changed}>
```

rect 用格坐标 `{col,row,cols,rows}`，candidate.data 是完整 LevelData；apply 核对 workspaceToken/beforeHash，旧预览不能覆盖其间新工作。完成后 dirty=true，内容 hash 变化且认证失效；随后导出只发起下载，不因导出清 dirty。失败、取消、存储不足不改图/历史/草稿/发布池。

作者三张原始副本不裁、不重写；B4 保真运行接入不以裁图作为前置。用户以后主动裁剪并确认，才生成相应新内容版本。

## 5. 现代扁平工作台

信息布局参考（使用现有原生 HTML/CSS/JS，不引入框架或外部服务）：

```text
顶栏：关卡名 · 地图尺寸 · 未保存状态 | 保存草稿 · 导出JSON · 试玩 · 发布 | 明/暗
左侧工具区              中央地图工作区                 右侧属性区
地形/机关/怪物分类       实际地图边界、端点与选择框       当前选中对象参数
画笔/橡皮/选择等工具     路径、局部检查高亮               地图尺寸/裁空白
云板起终点标记                                         接口检查/草稿列表
底部状态：坐标 · 缩放 · 地图大小 · 当前操作/保存反馈
```

功能分组用轻边框卡片、留白和层级组织；减少长段历史说明、拥挤表单和常驻原始 id/hash。主操作清晰区分“保存草稿”和“导出JSON”；高级元信息/路径坐标可折叠查看。地图是主要工作区域；右侧随当前选择显示相关属性，而不是同时塞满所有对象字段。

- 扁平中性色底、单一蓝色强调色、小面积状态色；禁用大渐变、厚重阴影、发光玻璃和过度装饰。
- 建议间距4/8/12/16/24px，卡片圆角8～12px，控件高度32～36px，字体沿用本地系统字体；图标配名称或可读提示，不能只靠颜色辨别工具/错误。
- 桌面参考：顶栏56px、左栏约220～240px、右栏约280～320px，中央自适应。1024宽时可折叠侧栏/卡片，控件不挤出窗口；1440×900/1920×1080正常操作。小屏保留菜单/操作可达，不扩展成手机编辑器。
- 保留既有快捷键、鼠标绘画、右键/空格拖动、缩放与撤销；输入框聚焦时不误触画笔热键。UI 重排不丢 B1 工作区令牌/异步保存、导入失败与 revision 冲突保护。

## 6. 深色/浅色主题

主题使用 CSS 语义变量，HTML、菜单/弹窗、表单、检查状态及 canvas 的工作区/网格/边界/选择框共用。地图贴图和游戏素材不因主题改变；切主题不改变 LevelData、hash、认证、dirty 或历史。

| token 示例 | 浅色参考 | 深色参考 |
|---|---|---|
| --editor-bg | #f3f4f6 | #0f131a |
| --editor-surface | #ffffff | #171d27 |
| --editor-text | #111827 | #e5e7eb |
| --editor-muted | #4b5563 | #9ca3af |
| --editor-border | #d1d5db | #343d4b |
| --editor-accent | #2563eb | #60a5fa |
| --editor-map-outside | #e5e7eb | #090d13 |

可按真实画面调整，但文字/禁用/选中/警告/错误均需两主题可辨。首次无设置可参考系统明暗偏好，之后用户明确切换优先。仅编辑器使用独立本地偏好：

```js
EditorPreferences = { schemaVersion: 1, theme: 'light'|'dark', autoGrow: false }
// 独立存储键建议 ra_editor_preferences_v1，不写入关卡/游戏存档。
```

设置写入返回显式成功/失败；失败时本次界面可继续生效，但提示“本次已切换，偏好未保存”，不误报重启会保留，不清关卡 dirty。读失败/未知偏好版本回退默认，保留旧数据并提示。加载主题尽量在首帧前应用，不闪整页错误底色。

## 7. 检查与交付原则

实现和人工步骤见16号卡：验证20×20在更大视图和DPR下仍导出20×20、显式扩图/撤销、裁剪坐标/未知内容/取消/容量失败、火球等屏幕放置后同 Session 可运行、固定场景不可编辑，以及双主题真实截图。UI 模拟不证明美观/手感，需对两主题实际检查。纯主题变化不升级规则；15号卡的新接口规则指纹已覆盖对应玩法变更。

15号卡先做新接口/作者三图，16号卡补编辑器与双主题；批内自行处理集成故障，最后运行专项与一次完整自检并同步最终离线包/APK，不为每个视觉小调整重复构建 Android。
