## 1. 流星锤只修编辑器显示

`RA.flailHead`的anchor/x/y是本图局部绝对像素。画布绘制统一一次变换：`screenX=(localX-view.x)*zoom`，Y同理；可用`cellToScreen(localX/TS, localY/TS)`，不能再加端点格的屏幕原点。锁链两端、锚点/锤头标识与4格辅助圆使用同一个坐标约定。

放置时保持初始正下方静态预览；地图非零col/row、缩放/平移、导入/裁剪后的预览都正确。按锚点、链条、锤头/轨道的可见包络判断是否应绘制，锚点在屏幕外但链或头可见时不能整件消失。只修该类型的绘制裁剪，不把所有对象强制全图绘制。悬停已有4格辅助圆可沿用，放下后的链/头与悬停一致。

这是坐标错误，保留现有占位外观；不更换资源、改col/row/params/半径/角度/正式运动来补偿。画布平移/缩放不写模型、不改hash/dirty/认证。

## 2. 删除路径对象的事务

需要修的是模型数据，而非只藏掉路线：

1. 收集**本次真正被删除对象**的非空pathId为候选。
2. 先得到本次删除后的objects；任意剩余对象仍引用候选id则该path保留（包括不同type/未知未来type的引用）。
3. 仅移除这些候选中已无引用的paths；其它路径、points/mode/未知扩展字段保持。
4. 连同原对象删除一次invalidate，由已有UI编辑事务统一dirty/撤销/重做；不产生第二个撤销点。no-op删除不改内容/认证/dirty。

覆盖removeObject、removeObjectsAt、橡皮/区域擦除及会真正替换删除对象的既有操作。缩小/裁剪等若走独立objects过滤分支，也应用相同“本次删对象的最后引用”收尾；不借机重做裁剪规格、物理或旧参数表。共享路径存在时，不能为了释放一个对象的私有路线破坏其它对象。

齿轮/移动火球的正常画布路线由对象创建、与对象生命周期一致；一点、往返、闭合均适用。创作中Esc/右键/切工具行为保持既有事务。已有JSON中的无引用路径继续保真导入/保存，不能加载/保存/打开关卡时做全局GC或静默删除作者数据；编辑器可不绘制无引用的旧路线（已放对象引用路线和创作中的当前路线正常显示）。这只处理旧残留的画面，不能替代新删除时真正清理paths。

撤销要恢复对象＋pathId＋完整路径（含未知字段）；重做一起移除；另一个对象仍引用时路径在删除/撤销前后均不变。删除内容使当前通过失效，但不删已有历史记录、不自动重新认证；下架发布版本与此模型编辑无关。

## 3. 两种正式来源要区分

| 来源 | 现在如何入池 | 如何移除 | 不受影响的内容 |
|---|---|---|---|
| 内置文件 | 已通过JSON放normal/difficulty-N，显式sync生成levels.js | 删除/移出对应源JSON→sync成功→刷新→新开始/重构 | 浏览器published、草稿、原始备份、当前run manifest |
| 浏览器发布 | 编辑器发布或设置导入后明确加入正式池 | 本卡设置中的单版本移出 | 磁盘JSON/内置catalog、草稿、通过历史、种子/最高分、当前run manifest |

Downloads等导出备份不是自动扫描目录，删它不改变任何已发布版本。id+contentHash是精确版本身份；同标题不一定同图，改图发布后新旧hash可同时存在。若想彻底撤掉一张图的所有版本，作者分别处理对应版本和来源；本轮不做隐式“全部版本”删除。fixed/fallback/archive不在普通下架范围，尤其test3池外补位不能当作者普通关卡删掉。

正式本局清单不可变，死亡重试仍原塔；移出只影响以后读取池的新局。开始会使用当前池，同seed可能生成不同塔；不主动更换保存种子或改已开始塔。

## 4. 最小下架入口

放在index主界面的设置中，与现有导入/池数量相邻。最小形态为浏览器发布版本选择列表＋“移出浏览器发布池”按钮＋结果说明，不新增首页主按钮、独立管理站或文件管理器。列表用标题/难度/id/短hash识别，始终保留精确id/hash作为选中值；同名不同版本可辨。只列真实当前浏览器published，内置不能冒充浏览器项。

提示本操作保留草稿/通过历史/磁盘文件。点击后可使用一次确认展示选定标题/版本；取消零变更。等待中禁重复点击，按点击时捕获的版本执行，异步回调不能删掉后来切选的另一个版本。成功后刷新列表/池数量；不存在的版本返回幂等“已不在浏览器发布池”，不报存储错误。

通过RA.NORMAL_LEVELS检测精确同id/hash的内置副本：列表/结果明确“还有内置来源，需移除源JSON并同步后才会完全退出新塔候选”，可以展示catalog的path帮助定位。只移除browser后不得显示“已从全部正式关卡删除”。纯内置图给磁盘操作说明即可，不加浏览器黑名单/墓碑或尝试从页面删文件；网页也不删除磁盘原件。

成功/失败不得重载当前编辑器草稿、清dirty、改地图hash/认证、历史最高分、seed文本或在玩manifest。无浏览器项时显示空态；存储失败保留选择/列表，不假报已移出，不自动切内存库假装持久成功。

## 5. 仓库接口（建议名，行为必须保持）

```text
ContentRepository.listPublishedVersions()
  -> Result<Array<{levelId,contentHash,title,difficulty,source}>>
ContentRepository.unpublish({levelId,contentHash})
  -> Result<{levelId,contentHash,removed:boolean}>
adapter.unpublish(levelId,contentHash) // Memory/IndexedDB语义一致
```

列表通过仓库服务读取当前epoch的真实published，不从drafts/通过历史推导发布，不补造通过声明；可在现有listPublished上做最小元数据映射。对不合格或不可运行的已发布记录也不要假装不存在：可显示原元数据/不可用状态，仍可按精确身份下架；不做几何/可达检查。当前epoch准备沿用已有一次性逻辑，不新增reset/clear或重复触发清池。

下架使用精确key `levelId + ':' + contentHash`，不只按title、当前草稿hash或levelId删全部版本。输入缺失/非法明确失败。IndexedDB仅对published做readwrite事务：读取是否存在，存在才delete；必须事务oncomplete才返回成功，request成功后事务abort仍为失败。不要直接套会提前resolve的通用助手；可参考现有put/publish的提交模式。保留drafts/metadata/通过历史，DB版本不变。

MemoryAdapter实现同结果语义，写失败/事务取消要能隔离构造验证；异常都转Result，不让按钮悬挂。UI只按实际成功更新，不在请求前乐观删掉列表。不需要服务器、联网撤销认证或多窗口锁框架；并发下同版本已被别处移除可返回removed=false，绝不能误删另一个hash。
