## 1. 确认的行为与本轮默认

用户要求金币/弓箭手可直接在编辑器放置，均无实体阻挡，不阻挡玩家、其它怪物，也不影响灵魂贴边。金币只被玩家拾取。弓箭手固定不移动、玩家正式进入所在层才启攻，每2秒向发射瞬间玩家位置发一枚直线箭，速度`V/2=170px/s`（V为正常地面最大移速340，不取玩家当前vx或空中上限）。箭矢不追踪、穿墙、不跨层。弓箭手本体及箭矢均造成伤害，光环只能消灭本体，不能消灭箭矢。

本轮实现默认：本体接触和箭命中均20伤害，沿用1秒受伤无敌时间/每模拟步最多一次伤害；弓箭手和火球一样被光环一击消灭。首次射击在入层后完整2秒，不是入层即射；弓箭手死后已射出的箭继续存在，直到命中、出界或离层。箭命中玩家后消失（包括玩家此时无敌），不贯穿玩家。这些为本卡默认，不表述为用户另行确认过的细节。

用户明确：**独立试玩不加入分数系统**。试玩保留同样的金币拾取消失、本体/箭矢攻击与伤害、技能和基础手感，只无计分HUD、计分状态/事件、结果分数及最高分写入。不得恢复塔装配、上下层、管道或Boss到TrialSession。

## 2. 模板、实例与编辑器

schemaVersion仍2；新增对象均放`objects[]`，不是terrain、路径或特殊地块：

```json
{"id":"coin_1","type":"coin","col":6,"row":8,"params":{},"pathId":null}
{"id":"archer_1","type":"archer","col":9,"row":10,"params":{},"pathId":null}
```

金币是collectible，弓箭手是hostile。固定值集中到config/rules，共享注册表描述；本轮不加生命/伤害/射速等参数面板。可以用类型判定函数最小扩展，勿引入完整ECS。建议默认金币圆形半径0.25格；弓箭手本体沿用火球默认0.5格判定半径；箭使用清楚可见、与实际朝向一致的细长占位图/命中框，尺寸在配置中唯一声明。美术后置不等于看不出金币、弓、箭及其方向。

编辑器增加两个直接放置工具，一次左键放一个，无方向/路径二次确认。连续拖画可沿用同类幂等笔刷；同格同type不重复，跨type保留，真实terrain/门/浮石/其它对象不擦。扩展“放置保真对象”的范围时应区分collectible与hostile，不能把金币当伤害怪物。橡皮/选中删除沿现有明确操作；撤销重做、裁剪平移、草稿、JSON往返、hash、试玩发布、四档文件同步及正式读取均支持两type。改动金币/弓箭手属于内容变化，需要作者重新试玩；绝不自动passed。

实例状态示意（不回写LevelData/paths）：

```text
coin instance: alive / collected
archer instance: alive, rx/ry, shotElapsed, facing
arrow runtime: id, ownerInstanceId, sourceObjectId, x/y, prevX/prevY, vx/vy, alive
```

每枚金币在每个实例/每局只能拾取一次；复用同一test3或同一模板的两个槽，各自对象独立。用角色身体与金币真实位置判定接触，光环不代捡。金币无HP/伤害，不可被光环“击败”。

## 3. 共享行为与箭矢边界

FloorInstance负责对象的实例状态/接触、弓箭计时和箭列表，或拆一个很小的共享辅助模块；GameSession/TrialSession调用同一套实现。共享层通过`damage`和可选的`onCoinCollected`/`onEnemyDefeated`通知会话，不能依赖DOM/最高分存储；Trial不实现计分回调也照常拾取/消灭对象。

- 只有active实例与running会话启攻、拾取、命中；preview可显示弓箭手/金币，不积累射击时间、不射箭、不伤害/收集/被光环消灭。入层开启完整2秒周期，暂停冻结。旧snapshot只保留地形，不显示金币/怪物/箭。离层清本层箭，停止攻击；F传送同样处理。
- 用游戏模拟dt，不能用setInterval/系统时间。每2秒一枚；不在暂停恢复或预热转active时补发一串。归一化发射方向，重合中心时用确定的朝向兜底，避免NaN。箭不追踪后续玩家移动。
- 所有位置比较前统一坐标：FloorInstance局部、Player世界坐标只能经origin转换。箭不参加terrain/solidAt/云板碰撞/BlockGeometry；与其它怪物、金币、链条和箭无碰撞，不因穿墙而修改地形。
- **不跨层包括视觉与伤害**：箭有ownerInstanceId，只能由所属active实例更新/绘制/伤害；不能随玩家转移到新层。箭到本图左右边界/所属层上下接口边界即消失；普通图以本层finish顶面为上界、start云板底面为下界，并与实际地图矩形取交集，连接管道不延长箭的飞行区域。无对应端口的固定场景边使用该图边界；单图试玩同样从本图派生，不生成管道。不使用原数组外侧空白扩大箭范围，不为此改World换层/碰撞/发布资格。
- 每步先裁剪箭线段到所属域，再判定该段与玩家身体的命中（或使用等价连续命中）；不能跨界后先伤到邻层再销毁，也不能高速一步越过角色漏判。击中后消费箭，无敌时间仅决定是否扣血。
- 会话死亡/胜利/重开/回主菜单/退出时停止并释放箭与射击计时；不泄漏到下一局，注册监听/rAF不重复。

## 4. 正式塔的积分真值

正式GameSession内持有本局非负整数`score`，初始0；是否启用由明确的正式运行身份决定（现`mode:'full40-formal'`，由`short.startFormal`传入），不能用“有run-v1”判断，因为试玩也用run-v1。不把规则塞入World、Player、HUD、浏览器事件队列或TrialSession。一个很小的RunScore helper可集中去重，也可放Session中；不要另建通用任务/成就系统。

| 事件 | 分值 | 唯一性 |
|---|---:|---|
| 首次进入真实层号1…40 | +20 | 本局按槽号一次，含10/30休息、20/40 Boss、0→1和20→21 F传送 |
| 敌对单位真的被击败 | +5 | 本局按instanceId＋objectId一次；Boss按Boss实例最终击败一次 |
| 拾取金币 | +10 | 本局按instanceId＋coin id一次 |

0层出生不加分，入40层后胜利不再加层分；层数总奖励固定800。可击败对象为静止火球、移动火球、灵魂、弓箭手及Boss；Boss掉第一个生命阶段不算击杀，两只Boss各完整击败加5。机械齿轮/流星锤/地刺/污水池、门浮石、箭及Boss弹幕等伤害物销毁、金币消失都不算敌人击杀。静止/移动火球在这里指关卡的敌人对象，不是Boss临时生成的弹幕。一次光环可对多个不同敌人分别加分；同一只活体只能产生一次击败。

从“alive→dead成功”“未收集→已收集成功”“首次真实入层”处同步加分，不依赖渲染帧、drainEvents次数或旧名`fireballDestroyed`。可发`scoreChanged {score,delta,reason,instanceId,sourceId}`供UI；UI只读取snapshot.score。老事件可兼容保留，不能同时累计两次。去重状态只在run里，单位消失的生命周期本身也应幂等。

正式入层/击杀/金币分在结算前落定。死亡/胜利后禁止新的拾取/射击/积分；最后Boss的5分先记，再win。重开本塔/死亡重试/再次开始都是新局0分，怪物金币重置，死亡重试仍原manifest；暂停/跨层不清分、不重建Player。启动失败不生成结果或最高分。

## 5. HUD、结果与唯一持久值

正式游玩右上角固定“得分 0”，更新为本局分；不挤掉左侧血条/技能/Boss条，不被右下暂停/布局工具遮挡。死亡和胜利界面都显示“本次得分 N”，与被冻结的会话score一致；回主菜单后本局状态可释放。试玩页面、试玩结果均无分数，也不触碰最高分模块。

主设置增加只读“历史最高分 N”，无记录列表/日期/最近分/种子排行。可用独立key `ra_high_score_v1`：

```json
{"version":1,"bestScore":0}
```

只持久化最高的非负整数；当前run/事件/seed/manifest/逐局分数不写入此键，也不增添挑战历史表。原有保存种子文本列表、作者通过历史/草稿不是本次要删除的记录，必须保留。首次无记录显示0。

建议正式积分刷新超过已保存best时提交一次max更新（不每帧写；没破纪录不写），可确保中途回菜单/退出也保留已获得的最高分；结果界面再读取一致值。持久化适配在short/平台层，通过Session通知连接，不让核心Session直接访问localStorage；试玩不接此适配。读/写返回明确成功或失败，写失败不能标为“已保存”，设置显示最后可信持久值及“最高分未保存/不可用”，本局分仍正常；临时最高值与已保存值分开。已有合法更高值不能被较低分覆盖，写前取max，异常/损坏数据不清其它键或整库。无须扩为多标签严格事务系统。
