# 试玩与正常游戏的控制、基础交互一致性

**30号新增边界（2026-11-09，待实施）**：用户明确试玩不加入分数系统：不建/累计/显示当前分，不写历史最高分。coin/archer及箭的拾取/攻击/伤害仍复用正式基础模块，只有塔生命周期与计分不接入。此决定覆盖下文“除上下层全部相同”可能产生的计分歧义，详见[30设计](coins-archer-and-score.md)。

2026-11-08，22号实现d41e07d实际启动未通过，见 [B4-R6验收](../checks/review-B4R6-2026-11-08.md)。23号卡已实施（B4-R7）[交付记录](../checks/B4R7-2026-11-08.md)：用户最新要求覆盖本文CD20/自动合规/大矩阵验收——除无上下关卡外与普通游玩相同，开局技能可用，以人工真实通过为准。见 [新契约](manual-single-level-play.md)。下文共用基础规则/不改Player数值原则保留，不按历史清单扩大任务。

## 1. 独立流程、同一基础规则

独立是指TrialSession自己管理单图生命周期和通过条件，不依赖塔GameSession/World的装配、换层、预热、F、休整、Boss。角色及对象仍必须按相同时间、相同输入、相同碰撞和交互规则运行。不能把独立理解成可以另写简化机关或按帧驱动物理。

保留现有Player、云板与邻接实心碰撞、尺寸、走速、二段跳/松手截跳/缓冲/土狼时间/落脚容错。已复现根因不在这些常量，不通过调参、增加跳数、无敌、传送、补平台修正观感。

## 2. 时间与模拟步

`TrialSession.update(realDt)`使用与正常GameSession相同的累计固定步策略：STEP=1/60，实际dt非有限或<=0视为0，MAX_FRAME=0.25、MAX_STEPS=5与当前正常游戏一致；本卡不擅自改变塔的追帧/余量语义。若提取纯FixedStepClock，两Session各持独立实例，TrialSession不得调用GameSession.update/stepOnce。

页面只算实际dt，核心累计足一整步才推进。无待处理余量时dt=0不移动、不改变动作边沿/计时；若长帧留下余量，按与正常游戏相同的追帧策略处理，不新加模拟时间。120次1/120秒不能执行120次1/60角色步。角色、对象路径/攻击、浮石/门状态、生命无敌、技能、试玩计时全部使用同一个STEP，不混用渲染dt。同一固定步的先后顺序与正常基础行为对齐。

参考顺序：消费动作边沿/技能 → 计时 → 对象非攻击运动 → Player移动碰撞 → 共用对象交互/伤害 → 共用光环效果 → 确认存活 → 本图终点判断/失败 → 事件。最终以当前GameSession实际顺序为准，避免本卡顺手改变火球接触与清除的先后规则。通过或失败后清累计余量和动作，立即中止剩余子步；暂停/恢复/失焦/重开不补算后台时间。

## 3. 输入

复用`js/platform/action-input.js`这类不含原生依赖的语义输入，或等价共享适配。按`key:KeyD`/`key:ArrowRight`等来源记录状态；释放只移除自己的来源，左右同时按按既有正常规则抵消。不要把布尔held写入复制到第三处。

Space/W/↑均为jump来源，逻辑合并后由Player判断首次按下/释放；按住Space再按W、松Space不能误产生松跳或第二跳。两次真实逻辑按下之间必须有释放，保持二段跳和松手截跳语义；浏览器repeat不制造连跳。K为按下一次的技能边沿，固定步只消费一次；不能在setActions或键盘回调里提前执行技能而角色还未模拟。

失焦/页面隐藏清所有来源/边沿并暂停；回前台保持暂停，用户继续后从新输入开始，不补后台时间。可复用纯浏览器生命周期辅助，不引入Capacitor依赖。手动暂停、结果、重开、离页也清动作；恢复时重置页面lastTime和核心累计余量。R/暂停/继续/重开按钮与键盘调用同一控制函数；监听和RAF随页面销毁清理。

## 4. 基础对象与技能

先复用已有FloorInstance基础对象方法或提取共享LevelRuntime/ObjectSimulation；只提取本卡用到的基础行为，不整包搬入塔状态。TrialSession应提供共用对象需要的最小上下文，例如player、events、time、damage(amount,source)；不要维护第二个简化`_objects`伤害表。

| 共用行为 | 试玩必须保持 |
|---|---|
| 门 | 正常接触触发broken、碰撞消失，本局不恢复 |
| 浮石 | 踩踏预警后消失、按参数恢复，玩家重叠时延迟恢复 |
| 弹簧 | 相同接触条件/弹力，正确清落地状态 |
| 齿轮 | 单点静止/直角路径移动、按共用碰撞盒扣血，光环不能击败 |
| 地刺 | 预警/伸出/回收周期正常，底座实心、活动期按共用条件伤害 |
| 火球/光环 | 同样接触伤害，技能范围内火球清除，渲染不再绘制已消灭对象 |
| 生命与技能 | 100生命、标准初始CD20，14/20规则、同一步最多一次伤害/无敌期、死亡先于通过 |

数值从现有RA.RULES.profile/tuning和C.OBJECT_PARAMS取；不把100/20/14/1秒等分别硬编码在TrialSession。单图对象坐标原点0，塔对象用真实origin换算；共享函数不能只在0原点正确。Trial的damage/技能可拥有独立状态与事件，但计算规则共用，不调用Boss或塔胜负。

## 5. 血条与技能反馈（用户本轮补充）

用户明确反馈试玩无血条/无技能。当前只有生命/冷却拼接文本及K入口，没有血条和可见光环，实际火球效果也漏接。修复必须同时覆盖运行效果与可见反馈，不能只恢复扣血或只改HUD文字。

- HUD始终显示生命条和当前/最大HP，用同一session.snapshot更新；伤害/无敌/死亡/重试时条宽与数值一致。生命条结构可复用short.html现有样式，不重新设计全编辑器。
- 明确K键与标准开局20秒冷却，显示冷却、就绪、活动剩余时间三态。冷却未到不施放，结束后可K；技能正常持续14秒、从施放起CD20秒，不把“初始不能用”做成永久无技能。
- 施放期间在角色周围画最小可见光环/有效范围，跟随角色与相机、范围来自共享数值；不是只播计数。实际火球在共用范围内被清除、齿轮/地刺不会被清除；过期/死亡/重试不留下旧光环。
- 暂停时范围与计时冻结，恢复不补时间。结果画面保留最终HP，重试满血/无光环/CD20。HUD不挡地图/控制，缩放后仍可读。基础圈/条与状态提示即可，不要求新美术资产/音效。
- 若提取HUD/光环纯渲染辅助，可供短塔与试玩复用；不引用塔状态或改变正式伤害规则。可见屏幕验收要能看到扣血条缩短、K就绪/施放/范围/火球消失，不能仅检查DOM节点存在。

## 6. 对照验证与认证

正常游戏对照采用GameSession同一张普通图/同起点/standard-v1配置，排除正式开局技能就绪与试玩CD20这种预期差异；本图内部路线避开finish或在通过前比较。另以已验六图确认塔行为未改变。

- 固定步动作轨迹：相同初态+动作，逐固定步比较位置/速度/落地/跳数/对象/HP/CD。真实渲染dt序列用30/60/90/120/144Hz及一次短抖动；输入按时间重放，不能以相同渲染帧号触发第二跳。允许不足一个固定步的采样相位差，不能扩大容差吞掉倍速/漏伤害。
- 分帧核心例：1次1/30与2次1/60应推进同等物理与机关；2次1/120合计一个固定步；无余量时0/负/NaN不模拟；暂停长间隔不推进或补算。长帧策略与正常对照一致，不借本卡重新定义全局时钟。
- 起步/停止/反向、短按/长按一跳、释放再二跳、落地后再跳、云板上穿侧移、别名键/左右同按、失焦恢复都要观察真实状态，不能只检查使用同一Player构造器。
- 每类对象做相同接触与时间推进的双会话用具，比较状态/伤害而非仅字段存在；用合成图验证真实死亡阻止通过，不直接给status赋failed冒充测试。
- 保留单图通过一次/冻结/重试与隔离内存认证→显式发布检查，不自动认证用户地图。与正式行为不一致的试玩会错误验证地图，修复时须升级rulesVersion/fingerprint（建议b4-5并加共享基础规则标识），旧b4-4认证保留只读历史但不自动续用/重签。

核心对照与页面替身不能证明显示器真实手感；可见屏幕从编辑器发起、用同一控制动作对比短塔需单独记录。无浏览器验证就明确未测，不让未实施/未验项目变成通过。
