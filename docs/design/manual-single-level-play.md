## 试玩规则

试玩就是普通游玩的当前一张图，没有上一关/下一关、生成支撑/石管/F/休整/Boss装配。普通游玩的Player、时间累计、输入映射、地形/实体、伤害、生命与技能、血条/状态显示、暂停和相机为基准，不另设简化玩法。原独立场景不要求再写一套物理/HUD；本卡复用现有实现并修实际接线，不借统一之名重做整个世界。

初始生命和技能直接取普通游玩profile（当前run-v1）：满血、光环开局可用；施放后14秒活动、从施放起20秒冷却。**取消旧试玩特有的初始CD20**。快照、handoff、认证与消费端须使用一致的普通profile身份，不能运行按run-v1却写成旧standard-v1。建议记录profileId=run-v1，移除各处“必须standard-v1”的固定判断，规则版本/指纹保留用于描述当次条件，不作为自动关卡合规替身。

本图start两格云板中心顶面出生；完整身体从下方上穿finish、脚底越过顶面且在两格开口内，产生一次通过并冻结。本图之外不生成可玩内容，失败可以重试同一图/返回编辑器；不跳入其他关卡或塔大厅。原云板单向、相邻石块四向碰撞及玩家尺寸/速度/重力/二段跳规则保留。

## 不再自动裁决关卡可玩性

- 不在编辑器发起、TrialSession.build、发布、正式候选或正式运行加载前进行几何、净空、最高/最低行、接口侧支撑、通道预留、怪物扫掠、自动可达性等关卡合规自检。已有完整validate(play/publish)包含这些内容，不能原封不动继续作门槛。
- 起终点通过编辑器鼠标标记记录；规则提示可用于帮助作者，但不后台静默阻断试玩/发布，不启动时再“正在验证”等待算法给通过。实现不需要新增一套预检面板或分析器。
- 只保留实际读取必需的防崩溃处理：文件能解析、网格能读取、运行需要的起终点数值/对象引用可用。失败显示具体读取/加载错误与返回入口，不悄悄删未知对象/扩图/裁图/挪出生点，也不能以“安全检查”之名恢复被取消的几何判断。
- 人工真实上穿finish产生通过回执，绑定实际内容hash与草稿身份；改内容不沿用别的图或旧版本的通过。没有人工通过不得伪造记录，下载/导入/自动检查不等于通过。
- 通过后明确保存记录，再由用户显式发布。发布及正式候选只确认内容可读取、确有匹配的人工通过记录；不能再调用旧几何/可达/标准初态门槛推翻人工结果。内容hash/revision保护用于防止认错图或覆盖新编辑，不是判断地图是否“设计正确”。旧记录完整保留，不因技术指纹变化自动批量作废；不自动重签passed。导入声明保留原来源，不冒充本机真人操作。

实现可给共享校验增加仅读取结构的用途或拆出最小加载器，但不重写编解码/仓库，也不允许仅删前端检查而让仓库/正式加载继续否决。正式塔的接口装配本身仍正常执行，不修改作者地图来满足旧检测。尺寸不统一，作者空白不裁。

## 启动、控制与错误

`trial.html`必须在trial.js前加载`js/platform/action-input.js`，不靠Node测试或其他页面碰巧提前定义。使用ActionInput的`held.jumpHeld`字段，pause动作在running分支外消费，P/Esc与按钮都能暂停/继续。R、重试、失焦/隐藏处理保持同一份输入与时间语义。

启动遇到缺脚本/实例化/首帧错误，结束启动状态并显示错误和返回编辑器入口；不能一直停在加载文案。资源缺失能用现有基础图形回退时正常进入游玩，不能把素材等待变成关卡检测。第一次绘制/输入实际可用后才称启动成功。

HP扣减、技能火球清除与场景绘制一致，alive=false对象不能继续画成存活；血条、K就绪/活动/冷却、可见光环按同一会话状态更新。初态开局可K，不再显示“开局20s”。不改角色常量补偿接线错误。

## 验收与交付

人工试玩为最高验收依据。编码agent应实际打开编辑器→当前图试玩，用屏幕键盘验证启动、走跳/二段跳、扣血与条宽、开局K及火球清除、暂停/继续、终点完成/重试；再确认手动发布后的同图可被普通游玩加载。人工失败即未通过，不以Node绿灯或自检数覆盖。

若浏览器无法操作，明确未人工验证并交给用户复测，不虚构屏幕/通关记录；诊断仅按需读取报错、检查脚本/字段与最小复现，不再要求全量关卡自检、自动寻路或大量对照矩阵作为交付门槛。代码语法/加载错误定位不等于关卡合规裁决。

每次给用户新任务卡时，在回复中附可复制提示词，写明任务卡路径、目标、必要约束和人工验证重点。提示词不只说“阅读所有文档”，也不授权一次执行后续整条路线。

## 已实现方式（2026-11-08 B4-R7）

- **试玩身份**：编辑器 handoff `profileId='run-v1'`；`RA.RULES.profile('run-v1')` = 满血、`haloActive:0`、`haloCooldown:0`。`TrialSession` 从 plan 的 profile 取初态（不再写死 20 秒），通过记录写 `profileId=plan.profileId`。`standard-v1` 只保留旧页面/旧记录语义；`acceptedProfile` 接受 `run-v1`/`standard-v1`，不再硬性要求某一个。
- **只读可运行检查**：`RA.LevelData.validate(data,{purpose:'load'})` / `readableIssues(data)` = 结构 + 网格 + 运行必需的云板 start/finish 整数格 + 对象类型/参数 + 对象→路径引用；`CloudPipe` 几何、最高/最低行、侧支撑、局部净空、`PathGeometry` 扫掠、可达性都不在 load 里。试玩页/编辑器/`ContentRepository.publish`/`publishImported`/`GameSession.create`/`listEligible` 全部改用或对齐它。
- **入口**：编辑器只有一个「▶ 试玩」；点击前用 `TrialSession.readableIssues` 检查并给具体错误，保存草稿后写 `RA_TRIAL_V3` → `trial.html`。
- **启动与错误**：`trial.html` 在 `trial.js` 之前加载 `js/platform/action-input.js`；`trial.js` 启动包在 try/catch 里，缺模块/缺数据/`TRIAL_*`/首帧异常都会结束启动状态，`trial-info` 显示"启动失败"、`dev-error` 显示具体错误 + 返回编辑器链接。
- **输入与暂停**：跳跃读 `held.jumpHeld`；每帧 `input.consume()`；pause 边沿在 running 分支外处理，P/Esc、暂停按钮、继续按钮共用 `togglePause()`；暂停与恢复都重置帧时间和 `TrialSession.accumulator`，恢复不追算。
- **共用表现**：对象绘制抽成 `RA.drawFloorObject`（短塔与试玩同一份），`alive=false` 的火球、碎掉的门、消失的浮石不画；HP 条宽度直接来自 `snapshot().hp/maxHp`。
- **发布/正式候选**：`publish` 只校验内容可读、`kind=normal`、回执↔草稿通过记录一致、内容 hash 一致；`listEligible`/`publishImported`/`certState` 与本地同一解释，不再比较规则版本/指纹（只作记录），仍要求 passed + hash 与内容一致。外部声明来源仍为 `imported-declaration`、只存草稿、需用户显式入池；无声明/改图不假通过。
- **返回原草稿**：结果页「返回编辑器」带 `editor.html?from=trial&draft=<draftId>`，编辑器只在明确返回时用 `openDraftById` 打开该草稿**最新已保存 revision**（含刚写回的通过记录），普通直开 `editor.html` 不读历史 handoff；保存中/已保存/未保存显示在结果面板，保存失败可重试，保存中点击返回会等保存完成，不误报已保存。
- 顺带修复：`IndexedDbAdapter.listPublished/getPublished` 原来读草稿 store，真实浏览器里发布后正式池读不出内容；改为读 `published` store。
- 规则版本 `b4-6`，指纹含 `trial=manual-single-map-v3`、`profile=run-v1`。工程/脚本化屏幕证据见交付记录；**真人键盘试玩仍需作者本人执行**。
