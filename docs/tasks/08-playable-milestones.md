## B1 — 能编辑、保存、试玩的连续两层

### 范围与内部顺序

1. **收尾 A3-C**：在完整候选副本中缩图/备份，通过共享校验/编码后提交；不足时返回 LIMIT_EXCEEDED，数据、历史、dirty、视角不变。只补必要回归，原复现见 [报告](../checks/review-T02AR-2026-11-01.md)。修完继续，不单独等待验收。
2. **接草稿保存**：IndexedDB save/load/list、draftId/revision、冲突与失败状态；刷新后可找回。保存按发起时快照，保存期间继续编辑不能误清新 dirty。保留 JSON 导出作为备份，不改旧发布池、不清旧存储。
3. **共用运行时**：新 GameSession 驱动开发试玩与新的游戏入口，复用现有物理；统一固定模拟时间、动作输入、暂停/后台。核心逻辑只一份，页面负责显示与文件/输入适配。
4. **两层连续世界**：宽高可变、统一端口、一次越线提交、同一玩家不重建；当前层完整运行，下一层非攻击预热，上层进入后才启用攻击/计时；上一层地形到再上一层才释放。
5. **把制作接到试玩**：编辑器可启动新运行时的开发试玩，不再降级 TXT；提供有明确入口的连续两层样例。至少四实例诊断夹具验证 n−1/n/n+1 生命周期，不要求制作正式四档内容池。

参考 [数据接口](../design/data-and-interfaces.md)、[世界规则](../design/world-and-gameplay.md) 和旧 [T03/T04](02-runtime-world.md)。实现模块路径可合理调整，不要求逐条照搬旧任务卡的过程描述。

### 第一批的明确取舍

- 采用原生 JS/Canvas 与现有资源、占位图，不引入框架、不重写物理、不提前做完整对象系统。
- 使用两张小型、满足端口规范的开发模板；旧 12 张原图保持原样，不要求全部修成新接口后才能交付。
- 新模板可以处于开发模式，无认证也能由作者调试；不得因此进入正式随机池、生成 passed 或宣称认证发布已完成。认证/发布仍在 B2。
- 保留现有 100 血/技能等状态接口的未来扩展边界；B1 不需要实现伤害、敌人或 Boss。预热可用简单移动诊断对象验证，不算敌人已完成。
- 接口先按既有宽 4 格、保护带 3 格提案实现并试玩；允许根据实际跳跃修订技术规格并同步文档，地图宽高可变与防回落规则不变。
- 暂不做历史塔 UI、完整资源注册器、视差、安卓、复杂装饰工具或完整自动寻路。

### 验收只看这几条主链路

1. **制作不丢数据**：打开含参数/路线/未知内容的 JSON，画图、撤销重做、保存、刷新恢复、导出重开，非目标内容保真；失败导入、存储失败与 revision 冲突不覆盖已有工作。
2. **能开始试玩**：编辑器有可用的新运行时试玩入口；不合法接口有明确提示，完整样例可直接开始，不靠修改浏览器控制台。
3. **两层确实连续**：至少一组不同宽高且偏置端口的地图可正常上升，位置/速度/跳跃状态不断；无淡出重生，过界不能回落，边缘不会卡死。
4. **生命周期正确**：进入第二层保留第一层地形，进入第三层才释放第一层；下一层提前运动但不攻击；暂停冻结模拟，恢复不追算后台时间。
5. **交付可启动**：实际启动入口、演示数据、已运行检查和已知问题写清楚；用户拿到工作区或相应提交即可操作。

运行适当专项检查，完成一次整批 `node tools/test_all.mjs`，报告真实结果及原有 floor09/floor11 的差异。测试以抓住以上行为为目标，不按 PASS 数量扩充。

实际浏览器验证一次“编辑→保存→刷新恢复→试玩跨层→暂停恢复”，记录版本与结果。自动浏览器起不来是环境限制：给出可由用户本地执行的简短清单，不反复重试同一个失败启动，不伪造通过，也不因此暂停所有独立实现。最终玩法体验需要该检查或用户补测支持。

### 风险与验收方式

- 会丢工作、破坏原文件、常用路径崩溃、核心规则错误、主链路不可用：本批必须修复，agent 自行继续到可交付。
- 罕见组合、轻微显示问题、开发工具易用性：记录进集中待办，按影响安排，不一律开新卡拦住整批。
- 已发现的 A3-C 本批仍须修；N01 仍作为非阻塞维护项，不把“加速”记成“已修复”。
- 验收聚焦这批约定的主链路及明显回归；新出现的非关键边界不无限扩展本批范围。不另设格式文档、截图命名或检查数量门槛。
- 不做未经请求的发布、远程推送或商店上架；提交/分支可用于回退，是否推送遵循用户当次安排。
