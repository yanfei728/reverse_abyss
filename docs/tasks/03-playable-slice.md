# T05～T08：第一版可玩闭环

共同输入：[世界与玩法](../design/world-and-gameplay.md)、[数据与接口](../design/data-and-interfaces.md)、[决定与调参](../design/decisions.md)。

## T05 — 战斗基础与三个代表对象

前置：T04。目标：能够躲避伤害并使用光环清场。

范围：RunState 生命/无敌/技能，静止火球、地刺、路径齿轮，已有机关新格式适配与浮石预警。注册表供未来编辑 UI 复用；先用正式格式样例驱动，不要求 T06 面板已完成。

必须实现：光环持续 14 秒、施放起 20 秒冷却、开局可用、跨层与暂停保留；普通敌人一击消灭，机械机关不受伤；接触伤害服从楼层 active 权限；同一模拟步不重复扣血；死亡清理本局并回大厅。技能按键初始提案 K、交互 E，新增时更新真实 README；不得改变现有跳跃按键。

地刺底座实心、伸出部分不阻挡；齿轮按 loop/pingpong 路径格中心移动；preview 齿轮运动但不能伤人。门与浮石移入 objects，不与旧字符重复生成；浮石踩踏预警后才消失，恢复不能把玩家夹住。

验收：t=14 活动结束、冷却剩 6；t=20 可再施放；暂停不计时；跨层不免费刷新；光环不能击败齿轮或提前清上层敌人；20 伤害规则下满血经五次有效受伤死亡，无敌期接触不累计扣血；重复模板的门不共享消失状态。检查 30/60/120fps 渲染下相同模拟行为。

人工体验：敌人和机关视觉可区分；光环范围与表现一致；受伤与无敌可读。暂定数值必须集中配置并记录调整。

不包含：普通攻击、其他角色、遗物、追捕、Boss 攻击。Boss 命中消耗光环可先通过契约测试，T07 接真实 Boss。

## T06 — 对象/路径编辑与发布认证

前置：T02、T05。目标：全部首版普通内容能由编辑器制作，通关后可靠入池。

范围：对象列表与参数面板、路径工具、PlaytestBridge、认证、Repository.publish/listEligible、编辑器与正式运行新链路整合。

必须实现：

- 放置对象后能在列表选中，修改注册参数，画格中心路径，选择 loop/pingpong；删除引用有提示；撤销重做覆盖属性与路径。
- 普通素材与固定场景权限区分；保护区非法内容可定位，未知类型不静默忽略。
- 标准试玩使用正式 Session、真实接口、独立不可变草稿快照；debug 与 standard 分开。
- 通关回执验证 sessionId、revision/hash、rules/profile；当前草稿改变后旧回执无效。
- 草稿保存、文件导出、发布分开；发布成功才修改池；未经认证与不兼容地图不能抽选。
- 发布后对象参数和路线在正式游戏中行为一致；正式游戏读取完整 LevelData，不走文本降级。

验收：完整人工执行“新建→放火球/地刺/齿轮→画路线→保存→重开→试玩通关→发布→在游戏抽到”；逐项核对对象与难度。然后改一格、改参数、改路线、改规则版本，旧认证都失效；旧窗口回传不能发布新图；存储失败池不变；同 id 新版本不修改已开始的一局。

认证标准配置按 B07 先实现并明确显示，若试玩显示过于保守再带记录讨论。人工认证不能自动由脚本填写 passed。内置测试夹具的模拟回执只能在测试内使用。

不包含：联网反作弊、分享平台、自动寻路认证、安卓编辑器。

## T07 — 休整、两阶段 Boss 与短塔

前置：T06。目标：大厅→三普通层→休整→Boss→胜利/死亡完整成立。

范围：固定场景控制器、休整回复、Boss 状态机与三种基础攻击、短塔 profile。完整 40 层和 NPC 剧情不进入此卡。

必须实现：

- 休整首次进入回复（初值 40、封顶 100），不能反复靠近边界刷回复；安全层无敌人/超时。
- Boss 两生命阶段：shielded→exposed→resolving→shielded/defeated。带盾阶段有可读预警的激光、弹幕、火球。
- 能量耗尽停攻、取消待发事件、清除全部 Boss 伤害体并关闭接触伤害；暴露无时间上限；基础跳跃+光环能命中。
- 有效命中扣一个阶段，清除该 castId 召唤物；不重置玩家技能冷却；Boss 未击败不得越过出口。
- 短塔随机抽选只用已发布的普通模板；内置兜底需实际人工认证；固定场景由工程试玩验收。缺内容时报错或明确兜底，不能假设所有旧图合格。
- 开局、死亡回大厅、重新挑战与简单胜利界面；短塔 HUD 明示测试楼层，不冒称正式 20/40 层。

验收：同一帧多次命中仅掉一阶段；旧弹幕/已排队火球不能在 exposed 后重新出现；t=5 命中消耗光环仍须等到 t=20；暴露时等待至少一个完整 CD 不受 Boss 伤害；近身技能可可靠打到；死亡优先于同帧胜利。

人工验收至少两次完整流程：一次通关、一次死亡重开；记录普通层耗时、掉血、Boss 等待时间与失败原因，不要求凭空达到某一平衡目标。越界处理须在本卡提供具体方案确认，不能自动沿用旧无伤重生。

交付调参表：攻击阶段时长、每种攻击的预警/间隔/速度/范围、暴露位置、光环半径与休整值。修改玩法数值后更新 rulesFingerprint 并重新确认对应认证。

## T08 — PC 短塔集成验收

前置：T07。目标：交付可复现启动、可编辑、可通关的 v0.1，随后转安卓。

范围：修复阻碍短塔闭环的问题、整理资源与脚本入口、同步生成数据、验收记录、更新 README/STATUS。不要顺手加入后续怪物或遗物。

必须验证：

1. 全部自动回归与新契约测试；旧 floor09/floor11 的处置有依据，废弃规则测试有替代项。
2. 新浏览器存储环境下启动，无依赖历史 localStorage；完整创建/编辑/试玩/发布/抽选流程成功。
3. 可变尺寸四类接缝、上一层快照保留、下一层预热且不攻击，暂停恢复不补算。
4. 14/20 秒技能、普通战斗、休整、两阶段 Boss、死亡和胜利实测。
5. 一份包含路线与对象的 JSON 导出后，在另一个干净浏览器环境导入并保真；认证来源正确显示。
6. 无效 JSON、未知对象、存储失败、缺失资源给出明确错误，不静默空场运行。

README 更新为真实新操作/启动方式，移除过时的“当前旧版”描述；STATUS 只有实际验收完成后才标 v0.1 完成。记录测试浏览器与环境，列出未测内容。此卡完成即进入 T09/T10，不能把安卓推迟到完整 40 层之后。
