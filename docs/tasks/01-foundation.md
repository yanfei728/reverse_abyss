## T00 — 建立可回退基线

目标：后续改数据/运行时前，保留当前能运行的原型和真实失败记录。

范围：仓库管理、环境记录与文档；不改游戏、关卡或贴图。当前目录不是 Git 仓库，优先建立本地版本管理基线；如果使用快照备份，需明确完整文件范围、存放位置与恢复方式，避免向源目录内部递归复制自身。不要把 README 归档当成全项目备份。不要覆盖用户已有仓库或修改。

交付：记录 Node/浏览器环境、原型入口、完整自检输出、当前文件清单、回退方法；保存到 `docs/checks/` 等明确目录。浏览器快速检查移动/二段跳/出口/编辑器；不能操作浏览器时保留未测标记。

验收：

1. `node tools/test_all.mjs` 记录原始退出码与失败。预期当前为 940/4；若不同，先解释差异。
2. 可以定位原始 12 张地图、HTML/JS/CSS/assets 和旧文档的回退副本/提交。
3. STATUS 中记录实际基线标识，不编造提交号；已知失败仍可追踪。

不包含：修地图、升级依赖、批量格式化、建立远程仓库或上传代码。

## T01 — 新关卡契约与无损迁移

前置：T00。目标：编辑器、运行时与工具将来读取同一数据结构。

涉及：新增共用 LevelCodec、迁移工具、EntityRegistry 参数描述基础；适配现有 level.js 的数据边界。保留旧游戏入口，先新增目标路径及契约测试，不能半迁移后让现有程序无法启动。

必须实现：

- schemaVersion=2 的解析、规范化 hash、分层校验、明确错误码；size 与网格精确一致。
- 注册表先提供首版对象的数据描述；尚未实现的行为不能宣称可运行。草稿允许保留未知对象，play/publish 拒绝。
- 旧 asc 地形及 S/x/y/P/G、objects、difficulty、sky 的迁移；旧 verified 不继承认证。
- 新迁移文件输出独立目录，原文件逐字保留；不合接口的旧图 ports=null 并给出修复提示，不自动裁剪。
- 给导入字节数、尺寸、对象/路径数等设置集中可调上限，并记录依据与需安卓复测；不设固定宽度。

数据例子：难度 3、两参数对象、一条 pingpong 路径、背景引用、extensions。序列化/重新解析后除明确派生 hash 外内容等价。

自动验收：对象键顺序不影响 hash；改一格改变 hash；路径断引用/未知参数/未来 schema/越界尺寸有错误；旧图迁移不丢对象与元信息；来源不修改；12 张旧图均有明确迁移结果和警告。

人工检查：打开一份新草稿，确认可阅读、字段有说明；不要要求人工通关才能保存迁移草稿。

不包含：完整编辑器参数 UI、敌人 AI、发布认证、连续世界。不能因为这些未实现就用旧 TXT 再保存新数据。

## T02 — 编辑器 JSON 往返与草稿仓库

前置：T01。目标：作者保存的就是完整地图，保存状态真实可靠。

涉及：editor.js 的 EditorModel/导入/打开/撤销重做/保存、ContentRepository；保留现有画笔、橡皮、矩形、填充、吸管、平移和缩放。

必须实现：

- EditorModel 以完整 LevelData 为真值；地形修改、尺寸修改、撤销重做不会重置其他字段。
- 导入/新建/草稿保存/打开/导出都使用 LevelCodec；旧 TXT 只作为迁移导入，不再作为新编辑器输出。
- 草稿与发布池分离；草稿 save 成功才更新保存状态；导出下载显示“已发起”，不声称写进游戏目录。
- 支持 expectedRevision 冲突检测；同 id 不同内容不静默覆盖发布版本。
- 修改后认证立即失效；发布流程尚未完成时按钮明确禁用或显示未实现，禁止临时绕过认证。
- 新格式试玩尚未接通时明确提示，不能转成 TXT 调旧试玩并丢字段。T03/T04 接通后解除限制。

自动验收：含难度 3、对象、路线、背景、extensions 的图执行“打开→画一格→撤销→重做→保存→重开”，所有非目标字段保真；覆盖取消、磁盘取消、存储失败、多窗口 revision 冲突不会改池或误清未保存状态。

人工验收：编辑器画图工具仍可用；草稿保存/文件导出/发布入口文案清晰；刷新后草稿可恢复；不完整地图可保存备份但不能试玩。

不包含：路径绘制工具、对象详细面板、通关认证实施。此卡不得改变当前正式池来掩盖未接通的新运行链路。
