# T09～T10：短塔之后优先安卓

用户已确认顺序：PC 短塔 → 安卓短塔 → 后续完整内容。PC 编辑器不移植到手机；移动端运行时需要支持关卡 JSON 导入/导出。

本文件是实施范围，尚无已验证 Android/Capacitor 版本或构建命令。实施时查阅所选版本官方文档、锁定依赖与工具链，并把实际可用命令写回 README，不能复制猜测命令声称已验证。

## T09 — Android 工程、动作输入与生命周期

前置：T08。目标：同一个短塔在安卓真机上可操作，核心玩法不另写手机版。

涉及：独立平台包装/构建配置、PlatformAdapter、输入 UI、暂停和页面生命周期；核心 GameSession 与 LevelCodec 复用。只打包游戏需要的资源和核心模块，不带编辑器 UI、开发工具与测试；不能误删共享解析模块。

必须实现：

- Capacitor + WebView 的本地离线运行壳，选择并记录 Android/SDK/依赖版本；开局不依赖本地电脑服务器。
- 横屏虚拟左/右、跳跃、技能、交互及屏幕暂停/设置；每个触点独立管理，多指按住不互相取消。
- 松开、移出、取消、失焦时正确释放动作；左右同时按住采用稳定规则（建议抵消），不会粘键。
- Android 返回键先关闭当前面板，再暂停游玩；后台立即暂停，恢复时保持暂停或明确等待继续，不补时间、不自动攻击。
- 暂停后光环/冷却/敌人/预热/超时均冻结；前后台不会再创建第二个模拟循环。

真机验收：移动+跳跃、移动+技能、多指快速切换、长按后切后台、返回键、锁屏/解锁、恢复后的冷却与位置。记录设备、系统、包版本、实际结果；只在桌面模拟触控不算真机通过。

输出：可安装的测试 APK（如果构建条件具备）、实际构建与安装说明、依赖锁文件、设备记录。环境缺失时先完成独立可测部分，明确阻塞点，不伪造 APK 或兼容性。

## T10 — JSON 往返、按键设置与安卓交付

前置：T09。目标：手机可以长期使用短塔，内容导入不需要重新打包。

必须实现：

- 系统选择文件→读取→共用校验器→应用私有仓库→发布池。已认证且兼容文件作为带来源的发布内容；未认证只进草稿/不可选列表并提示需 PC 标准试玩。
- 导出关卡 JSON 通过用户可访问的系统文件/分享流程；不能只把文件写到应用私有目录就宣称完成导出。
- 取消、权限失败、重复 ID、新旧版本并存、错误 JSON、容量不足均有可恢复处理；不修改已开始一局的模板。
- 按键大小和位置可调、保存、恢复默认；横屏安全区域变化后不把按钮放出屏幕。
- 真机离线启动、重启后内容保留、PC 导出→手机导入→手机导出→PC 重开完整保真。
- 完整短塔通关与死亡重开；记录明显卡顿场景及资源规模，按实测调整导入容量上限，不虚构帧率目标已达成。

验收文件必须包含可变尺寸、至少两个对象、一条路径、难度、资源引用及认证；不能只用空地图证明往返成功。实际系统文件流程必须真机检查，单测只负责字节与存储契约。

交付：APK/实际安装途径、已验证工具链与构建命令、支持范围、文件存放与备份说明、已知限制、更新后的 README/STATUS。涉及正式签名或商店发布是另一项工作，不默认上传或发布。

完成后再与用户讨论完整 40 层、四档内容、历史塔重温、超时追捕、传送门/敌人/遗物/角色等后续任务，不在此卡顺手展开。
