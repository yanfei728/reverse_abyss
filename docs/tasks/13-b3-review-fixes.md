## R1 · 按 pointerId 独立释放按钮（P1）

复现：同一个左按钮 down(11)→down(12)→up(11)→up(12)，sources=1、left=true。根因是 `setupTouchButtons()` 的单个 `source` 字符串被后来的触点覆盖，任一 up 又清掉该字符串。

- 每个按钮维护实际活动触点集合/映射，事件以自己的 pointerId 释放，不用“按钮最近一次来源”代替。也可明确拒绝同按钮第二触点，但必须保证旧触点的释放身份正确、结果稳定；优先沿用 ActionInput 多来源模型。
- up/cancel/lostcapture/leave 均按对应来源处理；无关 pointerId 不释放仍按住的触点，重复释放幂等。全抬起后来源为 0、held=false；抬一指保留仍按住的另一指。
- 后台、失焦、菜单/面板切换时一起清理输入与按钮追踪/视觉状态；不能只靠暂停兜底清除粘键。布局拖动也锁定实际拖动 pointer，避免另一触点劫持拖动或提前结束。
- 保留不同按钮多指、左右抵消、长按跳跃边沿与技能一次 press 的现有规则，不把恢复单触点模式当作修复。

回归执行实际按钮 DOM 事件绑定，不只测 ActionInput Map。至少同按钮两指先后抬起的两种顺序、cancel/lostcapture、无关 id、不同按钮释放、后台清空后再按。浏览器能运行时补真实 Pointer/Touch 路径；替身与真机证据分别记录。

## R2 · 同内容重导入更新过期认证（P1）

复现：旧规则 passed 声明先入草稿；相同内容在 PC 重新实际认证后再导入，返回 eligible=true，库内仍是旧规则，点击加入池报 CERT_REQUIRED。

- 对同 hash 的既有草稿比较完整认证有效性：status/profile/hash/rulesVersion/rulesFingerprint 及共享 publish 校验。不能仅以旧 cert 的 passed+hash 判断无需更新。
- 当前有效的新声明可更新旧/无效声明，并按 expectedRevision 原子写回；保存失败或冲突返回失败，旧草稿/池不变。读取既有记录失败要返回错误，不能误报本次 eligible 已保存或因空记录崩溃。
- 返回的 revision/eligible/source 必须对应最终持久化记录；同内容、同有效声明重复导入幂等。旧/无效声明不能覆盖现有有效认证或误报可加入。只是保存声明，仍须用户明确加入池。
- `publishImported()` 继续重新校验，来源 imported-declaration；不合成 local-playtest Receipt，不放宽旧规则/未知内容进入正式池的门槛。认证夹具只存在隔离内存中，真实关卡必须作者实际通关。

回归覆盖旧规则→当前规则（同内容 hash）、同有效声明重复、有效→旧声明、读取失败/写失败/revision 冲突，以及明确加入池后能被正式候选取到。不要清库或改内容 hash 来绕过旧记录。

## R3 · 草稿导入使用草稿门槛（P2）

- importLevel 的持久化门槛使用共享 draft 校验/编码：结构合法且在容量范围内，未知对象/参数、断引用、ports=null 等仅对运行不支持的信息可原样保留为不可选草稿。
- play/publish 校验决定是否可运行/加入池，明确返回具体 issues；未知内容不能因带认证而放行，也不能静默删除或改成已知对象。坏 JSON、结构错误/未来不支持 schema/超容量仍拒绝，不写半成品。
- 对未知内容和未补接口的合法草稿，导入后读回/导出保留原字段、参数、extensions；eligible=false、正式池不变。按实际问题提示“可保存、不可运行/发布”，不再把 play 错误说成草稿不可保存。

只改导入边界与必要 UI 反馈，不新增手机编辑器、重写编解码、全图迁移或降低发布规则。
