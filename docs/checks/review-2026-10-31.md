## 必须修复的问题

### R1 · P1：读写不对称，未知内容丢失与版本降级

位置：[level-data.js](../../js/level-data.js)，normalize 的对象构建约第 634 行，encode 的第 1240 行，以及 contentOf 的字段投影。

复现：在未知类型对象上增加 `behavior:{keep:'author-data'}`。直接 decode 返回成功，但 behavior 消失，warnings 为空。先 encode 再 decode 时，encode 成功，decode 却报 HASH_MISMATCH：写出文件的 hash 包含该字段，读回时字段被移除。

另一场景：把内存数据改为 schemaVersion=3 并添加 futureSystem，encode 返回成功，输出被强制改成 2，futureSystem 消失且无警告。

要求：已接受保存的草稿应能按同一契约重开；未知字段要完整保留或在丢失之前明确拒绝，不能悄悄改成另一份内容；未知对象仍要能保留草稿。对未来 schema 的 encode 与 decode 一样返回 UNSUPPORTED_SCHEMA，禁止隐式降级。hash、encode、decode 必须使用同一份内容规则。不能仅关闭 hash 校验来“修复”。

### R2 · P1：迁移工具在报错之前覆盖输入文件

位置：[migrate_levels.mjs](../../tools/migrate_levels.mjs)，第 31～32 行路径构造、第 110 行直接写出。

复现：只在系统临时目录创建 sample.json，将 --in 与 --out 指向这个同一目录。工具退出码 1，报告“原文件在迁移过程中被改动”，但原文件已经被替换为 schemaVersion=2。事后 hash 比对不能保护源文件。

要求：写入前规划并检查全部源文件、输出文件、报告文件的实际路径；源/输出相同、Windows 大小写或别名相同、输出 ID 归一化碰撞、报告覆盖源文件等情况，在任何写入前失败。已有人工修改的输出默认不覆盖，采用明确冲突/幂等策略。不要以运行失败后恢复正式地图作为正常防护流程。

### R3 · P2：空规则对象可绕过规则绑定校验

位置：[level-data.js](../../js/level-data.js)，validateCertification 第 1202～1220 行。

复现：认证不写 rulesVersion/rulesFingerprint，调用 publish 校验时传 rules={}，得到 0 个 error。原因是 undefined 与 undefined 比较相等。

要求：先独立校验当前 rules 和认证中的两个字段均为非空合法字符串，再比较；缺失、空串、错误类型都必须阻止发布。不能依赖尚未实现的 UI 保证调用方始终正确。完成时间也应符合约定的 ISO 时间格式。

### R4 · P1：旧数据迁移未完整保留待处理信息

位置：[legacy-import.js](../../js/legacy-import.js)，objects 构建约第 168～200 行、extensions 第 266～267 行。

复现：80 个未知字符只保存了前 64 个位置，迁移仍成功；未知对象的额外 behavior 字段和 pathId 被删除，原对象未保存在 extensions 中。只剩“曾经删除过”的警告，无法从新草稿恢复完整作者数据。

要求：保留原始未知记录及引用，或在数据上限内明确阻止迁移并保留原件；不能按固定数量截断后宣称无损成功。旧路径不存在可以标待修复，不应直接删除引用。补测未知对象、超过 64 个未知格、无法直接映射的旧元信息。正式 12 张图的成功不代表任意导入文件已无损。

### R5 · P2：导出能产生自身无法导入的大文件

位置：[level-data.js](../../js/level-data.js)，encode 输出阶段约第 1286～1287 行。

复现：未知对象的草稿参数中加入大字符串。encode 返回成功，输出 2,100,797 字节；同模块的导入上限为 2,097,152，decode 随即返回 LIMIT_EXCEEDED。

要求：最终输出按真实 UTF-8 字节数检查总上限；超限返回 LIMIT_EXCEEDED，不能静默截断字段或写出“保存成功但打不开”的文件。边界测试包含中文、格式化开销、单文件总量，不只测单个 extensions 限额。
