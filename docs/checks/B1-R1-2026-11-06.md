## 2. 实现

### 2.1 工作区令牌与保存上下文

`js/editor.js`：

- 新增 `workspaceToken`，每次 `newLevel()` / `replaceModel()`（打开 JSON、导入旧图、打开草稿）递增；撤销/重做不换工作区。
- `saveDraft()` 发起时捕获 `workspaceToken`、`draftId`、`expectedRevision`、完整快照与 hash。回包时：
  - 仓库仍保存**发起时快照**；旧图记录可以完成写入；
  - 若令牌已变化，不更新当前编辑器的 `draftId/revision/lastSavedHash/dirty`，返回 false，并提示"发起保存的旧图已保存，当前图没有被改动"；
  - 令牌未变时，只有当前 hash 与快照 hash 相同才清 dirty；保存期间同图继续编辑仍显示"当前仍未保存"。
- 因此"保存 A 期间切到 B"不会再把 B 绑到 A，也不会让 B 的保存覆盖 A。

### 2.2 开发试玩的一致性

`openPlaytest()` 在保存前捕获令牌、完整快照与 hash；`await saveDraft()` 之后：

1. 令牌变化（新建/导入/打开另一张图）→ 取消试玩，当前工作保留；
2. 保存失败/冲突 → 不离开；
3. `dirty` 或当前 hash 与快照不同 → 取消并提示"先再保存一次"，不把最新未保存内容带走；
4. 通过后把**刚保存的规范快照**（`LD.encode` 后再解析）放进 handoff，并再跑一次 play 校验；handoff 内容与草稿记录一致，不含保存后才产生的编辑。

不会出现"先保存旧版本、再把最新未保存版本带走"，也不会自动循环保存。

### 2.3 读取草稿的过期回包

`openDraftById()` 发起时记录：

- `_openSeq`：每次读取递增，只有最新请求的回包可以生效；
- `workspaceToken`：期间新建/导入/打开别的图则取消；
- 起始内容 hash：期间有任何编辑则取消，保留当前工作，不清 dirty、不替换历史。

两个读取请求乱序返回时，后选草稿仍然生效，先发后回的旧请求被丢弃。失败/取消/过期回包都不会改 dirty 或 revision 绑定。

### 2.4 N02 暂停重开

`js/devplay.js`：

- `setPaused(false)` 即使新 session 本来就不在暂停态，也显式隐藏遮罩；
- `restart()` 清空左右/跳跃输入、`lastT=0`、`pausedByPage=false`，给新 player 重新 `loadSprites(assets)`，再隐藏遮罩；
- 重开后新 session 从第 1 层开始、遮罩消失、角色贴图仍可用。

## 4. 已知限制

- B1 仍无战斗/敌人/技能/Boss、认证发布、端口编辑、安卓；这些不在 B1-R1。
- 两个读取请求乱序、慢保存切图等由 Node 可控 Promise 回归；真实浏览器只验证主链路与重开遮罩，未自动制造真实双窗口冲突。
- 保存期间禁止再次保存（`_saving`）是保守策略；用户需等当前保存完成。
- `openPlaytest()` 保存期间如果切图，会保留新图并取消试玩；需要用户在新图上重新点试玩。
- 系统文件选择对话框、真实手感、性能、安卓仍未人工验证；原 floor09/floor11 的 4 条诊断仍存在；N01/N02 之外的低影响项集中记录。
- 本轮没有清用户 IndexedDB、原图或历史证据。
