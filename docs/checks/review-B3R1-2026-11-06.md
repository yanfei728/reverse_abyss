### 优先排查方向，尚非确证根因

`short.html` 的 `#app`、`#menu`、`#settings-overlay`、暂停/结果/旋转覆盖层只用 `inset:0`，没有物理四边定位回退；`#wrap` 只用 `aspect-ratio` 给出高度。若相应 CSS 不受支持，覆盖层会失去预期包含区域，出现底部裁切；这是与用户截图吻合的兼容性假设。

MDN 官方兼容数据记录 Chromium/Android WebView 的 [inset 从 87 起支持](https://github.com/mdn/browser-compat-data/blob/main/css/properties/inset.json)、[aspect-ratio 从 88 起支持](https://github.com/mdn/browser-compat-data/blob/main/css/properties/aspect-ratio.json)。本地 Capacitor `Bridge.java` 的默认 WebView 下限为 60，而项目未覆盖该项；安装成功和桥接可用不能证明这些 CSS 受支持。需要采集真实 CSS.supports 和几何数据，不能声称已在旧 WebView 重现。

还应核查 `resize()` 读取 canvas CSS 尺寸后再写 backing-store 宽高时，是否反向影响容器高度；以及短横屏下菜单/设置内容溢出、系统栏与安全区域。当前 `browser_b3` 用 DOM `.click()` 启动与打开面板、以 session 存在判启动；即使按钮在屏外也可绕过布局，35/0 不能覆盖此次故障。
