## 1. 原因与证据

用户截图（[大厅](B3R2-user-android-menu-2026-11-06.jpg)、[布局](B3R2-user-android-layout-2026-11-06.jpg)）显示：画布区域黑、菜单/设置 box 只露出顶部，按钮在屏幕底部之外；不是贴图/物理问题。

代码审查确认旧 `short.html`：
- `#app`、`#menu`、`#settings-overlay`、`#pause-overlay`、`#result-overlay` 只用 `inset:0`，没有 `top/right/bottom/left` 回退；不支持 `inset` 的 WebView 会把 absolute/fixed 覆盖层放在静态位置，菜单/设置被推到页面底部。
- `#wrap` 依赖 `width:min(...)` + `aspect-ratio`，没有确定 CSS 宽高/JS 回退；画布/覆盖层没有共同的可视区域保证。

因此最可能根因是 **无回退的 `inset` + 仅现代 CSS 尺寸**；实际 WebView 提供者/版本未知，不能把假设写成已由 OPD2101 复现的根因。新布局不再依赖这两项即可成立。

## 2. 修复

- **CSS 基础回退**：`#app`、`#wrap`、菜单/暂停/结果/设置/旋转提示全部显式 `top/right/bottom/left`/宽高；`#menu`、overlay 使用 `overflow:auto`，box `max-height:calc(100% - 16px)`，短屏内部滚动。
- **确定尺寸**：`short.js` 的 `layoutViewport()` 从 `innerWidth/innerHeight` 计算 16:9 展示区，设置 `#wrap` 的 px left/top/width/height；canvas CSS 100%，backing store 单独按 DPR 设置。不再依赖 `aspect-ratio` 或 `min()`。
- **短屏**：`max-height:420px` 压缩菜单/设置字号/间距，必要时隐藏大厅说明；开始、关闭、保存、继续仍可达；布局面板不覆盖所有按钮且可关闭。
- **安全区**：touch container/设置按钮先写 0 值，再用 `@supports` 增强 `env(safe-area-inset-*)`；不支持 env 也有可用位置。
- **诊断/错误**：`RA.short.diagnostics()` 提供视口、wrap/canvas/menu/settings rect、DPR、session 状态；初始化异常显示可见 `#fatal-overlay`，不留纯黑不可恢复界面。
- **重复布局**：resize/orientation/visualViewport 统一走 `layoutViewport`；canvas 像素缓冲独立计算，不反复撑大容器。
- **保留**：布局 schemaVersion 1、旧布局按当前安全区夹回；不清用户存储；R1 多指、R2 重认证、R3 草稿保真代码未改。
