## 1. R1 · 同按钮多触点按 pointerId 释放

原缺陷：每个按钮只有一个 `source`，同按钮第二指覆盖第一指，任一抬起清掉“最近来源”，导致全抬后仍粘住。

修复（`js/short.js`）：
- 每个按钮维护 `Map<pointerId, source>`；down 只写自己的 pointer，up/cancel/lostcapture/leave 只释放同 pointerId；重复释放幂等；无关 id 不释放。
- 按钮 `active` 视觉只在集合为空时移除；两指同按保留 active，先抬一指仍按住。
- 后台/锁屏/暂停/菜单/重开统一 `clearTouchInput()`，同时清来源与视觉，不只靠 Session 暂停。
- 布局拖动锁定实际 `dragPointer`；第二触点不能劫持或提前结束拖动。

实际事件回归（`browser_b3`，真实 DOM PointerEvent）：
- 同按钮 down 11/down 12/up 11/up 12，两种抬起顺序，均回到 sources=0、held=false；
- cancel/lostcapture 只清对应触点，无关 pointerId 不释放仍按来源；
- 后台清输入且按钮 active 移除，继续后不粘键；
- 不同按钮多指、左右抵消、技能一次 press 保留。

## 2. R2 · 同内容旧认证→当前认证重导入

修复（`js/content-repository.js`）：
- 新增 `certState()`：完整比较 status/profile/hash/rulesVersion/rulesFingerprint，并跑共享 publish 校验；不再只看旧 cert 的 passed+hash。
- 同 hash 既有草稿：读取详情，比较旧认证是否仍有效；当前有效的新声明才以 expectedRevision 原子写回；写失败/冲突/读取失败都返回失败，旧草稿和池不变。
- 同有效声明重复导入幂等，返回实际持久化 revision；旧/无效声明不能覆盖现有有效认证；返回的 revision/eligible/source 对应最终记录。
- `publishImported()` 仍重新校验、来源标 `imported-declaration`，不生成 local-playtest；用户明确点击才入池。

回归：旧规则→当前规则同 hash 更新 revision 1→2 且可入池；重复当前声明幂等；当前→旧声明不改写；读失败/写失败/revision 冲突均不改旧草稿；浏览器真实 IndexedDB 重导入+重启读回当前认证。测试夹具均为隔离数据。
