## 取消关卡几何/净空/可达性自动门槛

新增"只读可运行"用途 `purpose:'load'`（`RA.LevelData.readableIssues`）：结构、网格、运行必需的 start/finish 数值、对象类型/参数、对象→路径引用。**不含**最高/最低行、接口侧支撑、局部净空、路径扫掠、自动可达性。这些旧判断仍留在 `validate(play/publish)` 里供历史诊断/夹具使用，但不再是放行条件。

| 消费端 | 之前 | 现在 |
|---|---|---|
| 编辑器「试玩」 | `validate(play)` 全量门槛 | `TrialSession.readableIssues`（结构 + 云板 start/finish + 对象参数/引用） |
| `TrialSession.build` | `validate(play)` + 必须 standard-v1 | 同上 + 接受 run-v1/standard-v1 |
| 仓库 `publish` | `validate(publish)`（含几何/净空/规则指纹必须当前） | 内容可读 + 内容 hash 绑定 + 回执↔草稿认证一致 |
| 仓库 `publishImported` | `validate(publish)` | 同上（导入声明仍要求声明规则与当前一致，避免把别处的旧声明当成本机通过） |
| `GameSession.create`（正式加载） | `validate(play)` | `readableIssues`；接口装配仍照常执行，不改作者地图 |
| `listEligible`（正式候选） | 规则版本/指纹必须等于当前 | 只要求 kind=normal、通过记录 passed、hash 与内容一致；规则版本仅作记录，不批量作废旧人工通过 |

保留内容：文件解析/结构错误、运行必需字段、未知对象/参数/断引用仍明确报错并阻止运行；草稿保存/revison 冲突/不自动清存储不变；导入声明仍保留原来源、不冒充本机真人操作；不自动生成 passed、不自动发布。

顺带修了一个真实阻断：`IndexedDbAdapter.listPublished/getPublished` 之前用草稿 store 读发布池（真实浏览器里会把草稿记录当发布记录，`levelId` 为 null，正式池无法加载）；改为读 `published` store。这是"发布后正式加载不因仓库问题继续阻断"的必要修复。

## 人工最短复测

1. 用本地静态服务器打开 `editor.html`（`file://` 也能用，但 IndexedDB 行为受浏览器策略影响）。
2. 「打开 JSON…」或「打开草稿」载入自己的图 → 点「▶ 试玩」。
3. 看：角色在地图 start 上、血条、K 就绪、没有上下管/关卡检测等待。
4. A/D 与 ←/→ 走；Space/W/↑ 起跳、松手后再按二段跳；P/Esc 暂停再按继续；R 重开。
5. 碰到齿轮/地刺/火球看扣血与条；按 K 看光环圈与范围内火球消失（齿轮/地刺不消失）；暂停时计时不动。
6. 走到本图 finish 从下往上穿过 → 出现"本图试玩通过"，页面底部说明已写入草稿。
7. 回编辑器 → 点「发布」→ 打开 `short.html` 选正式短塔，确认能抽到这张图。
