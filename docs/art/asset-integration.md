# 美术资产接入说明

核对日期：2026-11-01。依据当前 js/assets.js、js/level.js、js/entities/player.js、js/ui.js、tools/test_assets.mjs；以下区分“现在换文件就生效”与“需要 agent 接线”。没有修改或生成你的图片。

## 1. 现在最容易接入的素材

先备份原图，再使用同名 PNG 替换下表文件，刷新游戏或编辑器即可。不要改 PNG 扩展名来伪装 JPEG；像素画建议保留清晰像素边缘。图片只改变显示，碰撞/伤害仍由游戏逻辑决定。

| 用途 | 当前文件路径（项目根目录下） | 当前尺寸 | 准备建议 |
|---|---|---|---|
| 草地侧面 | assets/tiles/grass_top.png | 16×16 | 正方形瓦片，可用 16/32/64px，显示时缩放到一格 45px |
| 泥土 | assets/tiles/dirt.png | 16×16 | 同一套瓦片保持同样像素密度 |
| 砖块 | assets/tiles/brick.png | 16×16 | 同上 |
| 石块 | assets/tiles/stone.png | 16×16 | 同上 |
| 梯板/云板 | assets/tiles/cloud.png | 16×16 | 渲染只截取图片顶部一段，并画成约 13px 薄板；不要把主要图案只画在底部 |
| 弹簧 | assets/entities/spring.png | 45×45 | 透明背景，底部与格子底边对齐 |
| 浮石 | assets/entities/blink.png | 45×45 | 透明背景；外观不能改变其格子碰撞范围 |
| 旧出口光柱 | assets/entities/goal.png | 34×96 | 旧游戏仍使用；新连续接口由 T04 重做，不宜优先精修 |
| 天空 | assets/sky/sky1.png ～ sky8.png | 各 960×540 | 建议 16:9；当前为单张背景，按 cover 铺满并裁切，不是多层视差 |
| 标题背景 | assets/ui/title.png | 960×540 | 建议 16:9，为按钮和文字留可读区域 |

例如把石块素材另存成 `assets/tiles/stone.png`，打开 editor.html 看调色板与地块，再打开 index.html 验证游戏画面。遇到缓存用浏览器强制刷新。素材不存在时程序会用兜底图继续运行，所以“没报错”不等于新图成功加载；控制台查看 `[assets] 读不到 ...`，并实际确认画面变化。

## 2. 角色素材需要先注册

**当前角色仍由代码绘制兜底帧。** 虽然 Player.SPRITES 有 player/idle 等名字，但 js/assets.js 的 FILES 没有对应文件路径，loadAll 不会扫描目录。因此仅复制到 assets/images/player/idle.png 不会自动生效。assets.js 顶部的旧注释已不符合实际加载器，不能据此操作。

初始角色当前有五张独立帧：

| 动作键 | 建议文件路径（尚未接线） |
|---|---|
| player/idle | assets/characters/adventurer/idle.png |
| player/run0 | assets/characters/adventurer/run0.png |
| player/run1 | assets/characters/adventurer/run1.png |
| player/run2 | assets/characters/adventurer/run2.png |
| player/air | assets/characters/adventurer/air.png |

最省改动的交付规格：每帧 64×84px、透明背景、默认朝右、身体横向中心一致、脚底位于 y=80。现有 draw 按图片原生尺寸绘制，脚底锚点是 80；直接放不同尺寸可能导致大小不对、漂浮或陷入地面。游戏会自动水平翻转左朝向；碰撞盒目前 20×36px，与整张透明画布大小分开。

请保留素材本身的原尺寸原图；如果已有的是 32×32 或其他规格，交给接入 agent 配置显示比例与锚点即可，不必先把所有原图改坏。以上 64×84 是兼容当前显示的便利规格，不是最终强制美术标准。

接入 agent 需要在 FILES 注册五个键，例如 `player/idle -> assets/characters/adventurer/idle.png`，并检查加载完成后再读取帧、脚底锚点、翻转、跑步节奏及二段跳旋转。本轮仅给出方案，没有替你完成注册。

如果素材是一整张 sprite sheet/图集，当前加载器没有动画图集裁切功能，不能直接当 idle.png 使用；可以先导出五张独立帧，或单独安排图集/动画元数据任务。更多跑步帧、受伤/死亡/施法动作需要调整动画映射；不要为了迁就旧三帧丢掉原素材。

## 3. 尚不能只靠复制文件生效的内容

- 火球、地刺、齿轮等新敌人/机关：目前只有数据描述和编辑器占位，运行行为在 T05，显示与参数制作在后续接入；文件放好不会自动生成行为。
- Boss：状态机、攻击及暴露动作留 T07；可先整理待机、攻击预警、暴露、复活和击败素材。
- NPC 小人/立绘、技能光环、金币/红心、景物、塔内墙壁/窗户、多层背景：目前未完整接入，先提供原文件、用途、锚点/图层说明，按对应模块登记。
- 把图片放进 assets 不会自动让它出现在编辑器调色板；新增资源键、实体类型和允许场景需要显式配置。

当前背景是八张单图；最终的大厅独立背景、四组视差和塔内背景是后续结构，原图可以先整理为“远景/中景/近景”，不强行把它们合成一张而丢失分层文件。

## 4. 避免素材被工具覆盖或测试误判

- `node tools/build_assets.mjs` 会重生成实体/天空/标题 PNG，覆盖这些路径的自定义美术。`--restore-tiles` 还会覆盖地块。替换后不要把此命令当启动或修复命令运行。
- 目前贴图测试对实体/天空/标题做“与生成器逐字节相等”断言。你换成自定义图后，这类断言会失败，即使图片已正确加载；不能因此把你的图换回旧图。
- 美术正式接入时让 agent 将这类断言改为 PNG 有效、引用可解析、必要尺寸/锚点/透明度与真实加载检查；保留素材逻辑回归，不简单关掉整个测试。
- 地块当前主要检查 PNG/尺寸及缩放行为，不要求与生成器逐字节相同，是现在最适合先替换的一组。

## 5. 交给接入 agent 的素材清单

保留原始素材目录，另提供如下表格即可；不必先手写代码或全量重命名。

| 原文件路径 | 用途/角色 | 格式与尺寸 | 帧数/顺序/FPS | 朝向与脚底/中心 | 目标资源键或备注 |
|---|---|---|---|---|---|
| 填你的实际路径 | 初始角色跑步 | PNG 图集或多帧 | 按素材实际情况 | 例如朝右、脚底同一基线 | player/run... |
| 填你的实际路径 | 石块 | PNG 32×32 | 单张 | 无透明边距 | tiles/stone |
| 填你的实际路径 | 塔外远景 | PNG | 单张 | 图层：远景 | 后续视差组 |

推荐接入顺序：先地块风格 → 初始角色五帧 → 三种代表敌人/机关 → 光环与 Boss → NPC/多层背景。先抽一组小样确认尺寸与锚点，再批量接入。

## 6. 独立美术接入任务提案（用户提供路径后执行）

ART01 建议只接一套地块与初始角色：盘点原文件、复制运行用导出物、建立 FILES 映射、显示比例/锚点、调整不适合自定义图的旧测试、浏览器验证。图片源文件不覆盖；不顺手改物理或敌人行为。若只想自己换石块/砖块，按第 1 节替换即可，无需等待 ART01。

准备好后，把**素材所在文件夹的实际路径**发给规划/接入 agent，注明先接哪个角色或哪套地块，即可据实际文件写下一张具体美术任务卡。
