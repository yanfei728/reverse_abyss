# reverse_abyss · 向上爬塔

`abyss/`(Python + pygame 的 2D 跑酷小游戏)迁到网页上之后的**向上爬塔**版本。
HTML5 + 原生 JavaScript,没有构建步骤、没有依赖,贴图是会自己兜底画出来的 PNG ——
**双击 `index.html` 就能玩**。

塔是往上爬的:一层一层往上,每层都是**关卡池里现挑的一张独立关卡**,
所以每层结构都不固定;塔的结构在开局界面的**设置**里按 `R` 可以**重构**。
同一个种子永远长出同一座塔,把种子抄下来就能让别人爬你那座塔。

关卡想自己画:**双击 `editor.html`** 就是关卡编辑器 —— 笔刷式的,大小不限,
必须画起点和出口,能画的"地物"直接从引擎里读,所以以后新加的地块 / 机关
编辑器里会自动出现(`editor.js` 一行都不用改)。

贴图也全拆成了**独立的 PNG 文件**:`assets/tiles/` 是关卡地块(第七轮换成了 `textures/block`
那套 16×16 的像素画,画的时候缩放到一格)、`assets/entities/` 是弹簧板 / 出口光柱 / 浮石这三样实体、
`assets/sky/sky1~8.png` 是天空(爬塔时**按层循环**,关卡也能在 json 里写 `"sky": N` 固定用某一张)、
`assets/ui/title.png` 是开局界面的背景。换风格直接用画图软件改这些 PNG ——
地块、天空、界面都不用重跑脚本;只有实体 / 天空 / 界面那几张是 `tools/build_assets.mjs` 生成的。

## 运行

| 方式 | 命令 / 操作 | 说明 |
|------|------------|------|
| 直接打开 | 双击 `index.html` | 关卡数据用 `levels/levels.js` 里内嵌的那份 |
| **关卡编辑器** | 双击 `editor.html`(或游戏里「设置 → 关卡编辑器」) | 用笔刷画楼层,试玩 / 下载 txt / 保存到游戏(**它写的还是老格式 txt**,见下面「编辑器」那几节) |
| 本地服务器 | `python -m http.server` 然后开 `http://localhost:8000/` | 会实时 `fetch` `levels/<id>.json`(读不到 json 就退回读老格式 `levels/<id>.txt`),改完刷新页面就生效,不用同步 |
| 浏览器自检 | 打开 `tests/browser.html` | 在页面里把整套自检跑一遍,结果直接打在页面上 |
| 命令行自检 | `node tools/test_all.mjs` | 引擎 + 编辑器 + 试玩页 + 贴图共 941 项检查(含逐跳物理模拟),`--fast` 时只剩两条关卡设计的失败 |
| 只测引擎 / 只测编辑器 | `node tools/test_engine.mjs` / `node tools/test_editor.mjs` | 加 `--fast` 跳过逐跳物理模拟 |
| 关卡检查 | `node tools/check_levels.mjs` | 打印地图 + id / 难度 / 已验证 / objects + 逐跳可达性,不开游戏就能看出一层能不能爬上去(默认扫 `levels/*.json`,老格式 txt 也认) |
| 重新生成贴图 | `node tools/build_assets.mjs` | 重画实体 / 天空 / 界面贴图(地块是贴图包里的图,不在它管辖内);`--restore-tiles` 才连地块一起重画成旧样式 |

> 只有 `node`(≥ 18)是可选依赖,而且只给工具用;游戏本身零依赖。
> 改了 `levels/*.json` 之后记得跑一次 `node tools/sync_levels.mjs` 把它们重新打包进
> `levels/levels.js`(忘了跑也没事:自检会报"levels.js 和 json 不一致")。

**落地/脚步音效**、**掉出世界自动回本层起点**(爬塔里它只是一次"坠落",会记进结算)。

## 从 abyss 迁移过来:对照表

引擎是按"一个文件对一个文件"搬的,物理数值一个都没改,所以手感是同一套。

| abyss(Python / pygame) | reverse_abyss(Javascript / canvas) | 说明 |
|---|---|---|
| `game/config.py` | `js/config.js` | 物理/镜头数值原样照搬,后面加了爬塔的参数 |
| `game/level.py` | `js/level.js` | 字符地图、瓦片碰撞(先横后纵)、`TILE_IMAGES` 表都一样 |
| `game/camera.py` | `js/camera.js` | 双轴镜头策略一样;多了"世界比屏幕窄就居中"和一个 `panY` 偏移量(爬升早就不用它推整层了,现在是 0) |
| `game/entities/base.py` | `js/entities/base.js` | `BY_LETTER` 注册表、`@register` → `RA.register`,一个字符一个类 |
| `game/entities/player.py` | `js/entities/player.js` | 手感逻辑逐行搬;按键换成 `{left,right,jump}` 对象 |
| `game/entities/goal.py` | `js/entities/goal.js` | 旗子 → 「上一层」的光柱出口 |
| `game/util.py` | `js/util.js` | `clamp` 等小工具 |
| `game/assets.py` + `build_assets.py` | `js/assets.js` | 原来是"预生成 PNG",现在**运行时用 canvas 现画**(同一套画法/配色) |
| `game/audio.py` | `js/audio.js` | 原来是 pygame 合成波形,现在用 Web Audio 振荡器合成 |
| `game/ui.py` | `js/ui.js` + `js/text.js` | 界面照样全代码画,没有 UI 素材 |
| `game/game.py` | `js/game.js` | 状态机从 2 个状态扩到 5 个(标题 / 设置 / 游玩 / 爬升 / 结算 + 告别页) |
| `game/smoke.py` | `js/smoke.js` | 物理自检逐条搬过来,再加塔和关卡池的检查 |
| `tools/check_levels.py` | `tools/check_levels.mjs` | 打印地图 + 校验;原来模拟"一路向右",现在逐跳模拟"往上爬" |
| `levels/*.txt` | `levels/*.json`(地图在 `asc` 字段里) | 地图的字符表完全一样 —— `floor08.json` 的 asc 就是 abyss 的 `level01.txt`,一字未改。新格式只是把这张图包进 json,再补上 id / 难度 / verified / size / objects |
| `main.py` | `index.html` + `js/main.js` | 入口 |

### 迁移时有意改掉的几处(以及为什么)

1. **方向反过来。** 地图里没写 `P` / `G` 时的自动兜底变了:出生点放**最下面**那块地面、
   出口放**最高**那块地面 —— 向上爬的关卡天然长这样。出口的判定也从"旗杆"换成一个
   方盒子(`GOAL_WIDTH × GOAL_HEIGHT`),不会再出现擦着旗杆就算通关的情况。
2. **一层 = 一张独立关卡,塔 = 一串层。** 新增 `js/tower.js`:按种子从关卡池里给每层
   抽一张图(相邻几层不重复),可以镜像、可以随时重构。
3. **层与层之间多了个切换过渡。** `game.js` 里的 `climb` 状态:旧楼层渐出 → 中间压一层
   暗场 → 新楼层渐入,天空同时从旧天空交叉淡化到新天空 —— 爬塔的重点就是"往上"那一下。
   (最早是"整层上下推":旧层往下走、新层从上面降下来。推的时候两层在屏幕里叠着、
   而且整屏都在动,看着晃;第六轮换成了渐入渐出。)
4. **素材从"现画"变成落盘的 PNG。** 一开始照 abyss 的路子把图现画在离屏 canvas 上,
   项目里一张图片都没有;现在地块 / 实体 / 天空 / 界面都是 `assets/` 下独立的 PNG,
   所以不存在"少图"的问题 —— 每张图都留着一份现画的兜底。
   地块那 5 张在**第七轮换成了 `textures/block` 那套 16×16 的像素画**
   (画的时候缩放到一格,所以尺寸和格子不一致也没关系);实体 / 天空 / 界面还是
   `tools/build_assets.mjs` 用代码画的。想换成自己的图:直接替换 `assets/` 下对应的 PNG。
5. **多了一个新实体 `S`(弹簧板)**,顺便当"怎么给引擎加一个新东西"的活例子。
6. **Python 的"类属性"在 JS 里不存在。** `player.MAX_VX` 这种写法在 Python 里能从实例读到
   类属性,JS 的 `static` 不行 —— 所以 `player.js` 最后给这些数值加了一层访问器,
   让 `player.LEDGE_ASSIST = 0` 这种调试/自检写法照样有效(行为与 Python 对齐)。

## 爬塔是怎么运作的

```
levels/*.json / levels.js ─┐
                           ├─→ 关卡池(唯一组装点 RA.LevelPack.poolOf)
游戏里「导入关卡」的 txt / json ┤        · 同 id 只留一条
编辑器「保存到游戏」的覆盖 ─┘        · 同一个 id / 关卡名在浏览器里也只算一层
                                    ↓
                           塔(Tower):按种子给每一层抽一张图 ─→ 第1层…第N层
                                    · 相邻 TOWER_NO_REPEAT_GAP 层内不重复
                                    · 每层可以镜像(同一张图两种走法)
                                    · 同一个种子 = 同一座塔
```

* **重构**(设置里 `R`):换一个种子重新抽层 —— 塔的层数不变,结构全换。
  每次重构都会**重新拼一遍关卡池**,所以编辑器刚存进去的层立刻就能抽到。
* **种子**(设置里点种子框输入):把种子抄下来,同一个种子会重新长出同一座塔。
* **塔高**(`↑↓` / 点 `＋` `−`):3~24 层。塔是**顺序**生成的,所以加高不会改变下面几层。
* **镜像**:模板左右翻一下就是另一条路线,关卡池小的时候靠它把变化拉大。
* **爬升**:角色碰到「上一层」的出口 → `climb` 状态 0.85 秒(旧层渐出 → 中间暗场 →
  新层渐入,天空交叉淡化)→ 落到上一层出生点。新层是从**它自己的镜头**开始的,
  不做上下推整层那套。
* **坠落**:掉出本层世界底部不算死,回本层起点,结算里记一次"坠落"。
  (想改成"掉一层"也很简单:见下面"下一步扩展"。)

## 怎么设计楼层

**一层 = `levels/` 里的一个 json 文件**(`<id>.json`),地形还是用字符"画"出来的,
只是画完的这张图放进 json 的 `asc` 字段,元信息(难度、天空、带参数的元素)也写在同一个
json 里。行号从上往下、列号从左往右,一格 45px。字符表和 abyss 完全一样。

**为什么从"纯地图 txt"换成"asc + json"**:地图文本一眼看得懂、能手改,这个好处必须留着;
但一层关卡还得记住"它多难、验过没有、这层有没有火球"这类**带名字、带值**的东西 ——
塞进一行注释里不像话,也不该让引擎去猜。所以变成:能一眼看懂的还是那堆字符
(一行一项的字符串数组),其余的摆在 json 字段里,谁都能读、谁都能改。

`levels/floor01.json` 的头几行长这样:

```json
{
  "id": "floor01",
  "difficulty": 1,
  "verified": true,
  "size": { "cols": 22, "rows": 32 },
  "sky": 0,
  "objects": [],
  "asc": [
    "++++++++++++++++++G",
    "++++++++++++++++++~~--",
    ""
  ]
}
```

字段就这几个:

| 字段 | 是什么 |
|---|---|
| `id` | 关卡的**固定身份**,要和文件名一致(`floor01.json` 里就是 `floor01`)。**关卡的"名字"已经全部去掉了**,一层就叫 `floor01` … `floor12`(原来的 floor01–floor08 不动,北落 → `floor09`、新楼层_3 → `floor10`、浮石 → `floor11`、深界 → `floor12`)。HUD、塔结构表、提示显示的都是这个 id |
| `difficulty` | 难度,1~4 档(现在 12 层都是 1 档) |
| `verified` | 是不是"验过能通"的关卡(`true` / `false`,现在都是 `true`) |
| `size` | `{"cols": N, "rows": N}`。和 `asc` 对不上会被提醒一句,**以 asc 为准** |
| `sky` | `0` = 天空随层数循环;`1~8` = 这一层固定用那一张 |
| `objects` | 带参数的元素(怪物 / 以后的机关),现在都是 `[]` —— 见下面「带参数的元素」 |
| `asc` | 地图本体,**一行一项的字符串数组**(所以地图在 json 里照样一眼看得懂、能手改);也接受一整段带换行的字符串 |

`asc` 里每一行用的字符:

```
++++++++++++G++                + 或空格 = 空气
+++++++++++^^^^                ^ = 草地    _ = 泥土
+++++++++^^^^++                ~ = 砖块    = = 石块
+++-------+++++                - = 云板(单向:从下往上能穿,从上往下会被接住)
+^^^^++++++++++                P = 出生点(放地面上方那格)
++P++++++++++++                G = 出口「上一层」(会自动落到下面的地面)
^^^^^^^^^^^^^^^                S = 弹簧板
===============                x = 触之即散(碰到就消失,有碰撞体积)
                               y = 浮石(踩到就消失,过一会儿回来,有碰撞体积)
```

规则和小技巧:

- **加一层**:复制 `levels/_template.json` 改个文件名(`_` 开头的不算关卡),
  里面的 `id` 也要跟着改成文件名。或者用编辑器建一层再「保存到游戏」——
  但**编辑器这轮写的还是老格式 txt**,见下面「编辑器」那几节。
- 想固定这一层的天空,把 `"sky"` 写成 1~8;写 `0` 就是随层数循环。
- **行尾不用写满**,自动补空;每行不一样长也没关系(按最长的那行补齐)。
- **向上爬的楼层**:`P` 放最下面,`G` 放最上面。两个标记都会自动落到自己正下方的地面上。
- 台阶高度(一格 45px,都是实测值):
  | 怎么跳 | 能上多高 | 横向大概能挪多远 |
  |---|---|---|
  | 一段跳 | 约 150px(2~3 格) | 约 160px(3 格多) |
  | 二段跳(空中再按) | 约 300px(5~6 格) | 约 370px |
  | 弹簧板 `S` | 约 300px | 约 200px |
  | 落脚容错 | 差 22px 以内会自动送上去 | — |
  留富余量,别顶着极限设计。
- **行数 > 12** 世界就比屏幕高,镜头开始上下跟随;**列数 > 21** 就需要横向滚屏
  (`floor06` 是 30 列宽、`floor08` 是 43 列宽,都靠横向滚动)。
- 想让玩家"掉下去"有代价:在地面留个洞,掉出世界就会回起点。

### 带参数的元素(`objects[]`)

一个地图字符只能写一个字,带不了"速度 120、往左飞、打两下才没"这种参数。所以这类东西
不写进 `asc`,而是写进 `objects[]`,长这样(现在游戏里还没有任何一条):

```json
"objects": [
  { "type": "fireball", "col": 3, "row": 5, "params": {} }
]
```

* `type` 是元素类型,现在表里只有一条 `fireball`(火球)**参数先空着**,
  在哪、默认值多少写在 `js/monsters.js`(`RA.Monsters.get / ids / defaults / paramsOf`);
* `col` / `row` 是格子坐标;
* `params` 是这一条自己的参数,和表里的默认值合并,**关卡里写的说了算**。

引擎认得这个格式,会把它读进 `level.objects`;但**现在还没有火球的行为**,也没往任何一层
塞过示范。等要真的动起来的时候:在 `js/entities/` 里写一个实体类、类上写一行
`Fireball.type = 'fireball'`,再 `RA.register` 一下 —— 关卡里那些 objects 立刻就会
自动生成实体(`js/level.js` 的 `_buildObjects` 配 `js/entities/base.js` 的 `BY_TYPE`)。

**动笔前后都跑一遍检查**,省得在游戏里反复试:

```bash
node tools/check_levels.mjs                     # 检查全部楼层(默认扫 levels/*.json)
node tools/check_levels.mjs levels/floor03.json # 只检查一层
node tools/check_levels.mjs --no-sim            # 只做跳跃包络估算(快,但只是估计)
# 不带 --no-sim 时:包络只用来粗筛,结论一律以"真物理逐跳模拟"为准
```

它会把地图连行列号一起打印出来,顺手报一遍这一层的 **id / 难度 / 已验证 / objects**,
然后报告问题(不认识的字符、出生点悬空、出口没插在地上……),最后**用真物理一跳跃一跳跃地
模拟**"从出生点能不能爬到出口",把每一跳的上升高度 / 横向距离 / 起跳时机都列出来。
模拟能过,人就一定能过。

加一层 / 删一层 / 调顺序:加 → 复制 `_template.json` 改名(记得改 `id`);删 → 删文件;
调顺序 → 改文件名(`floor01` 想排后面就改叫 `floor13`,文件名就是 id)。改完跑一次
`node tools/sync_levels.mjs`:它把 `levels/*.json` 打包进 `levels/levels.js`,顺便把每个
json 体检一遍 —— **id 要和文件名一致、难度在 1~4、verified 是布尔、size 与 asc 对得上、
objects 是数组、sky 合法**,有问题直接报错退出,不生成半成品。
`levels/` 里要是还留着老格式的 txt,它(和自检)会**提醒一句**:引擎读得进来,但那不是关卡
源头、也不会被打包。

## 关卡编辑器(editor.html)

不想手敲字符就用它:**双击 `editor.html`**(游戏里「设置 → 关卡编辑器」也能开)。

中间是画布,左边是地物和工具,右边是关卡设置和检查结果。

> **这一轮编辑器还没接新格式(重要)。** 关卡数据已经从"纯地图 txt"换成了
> `levels/<id>.json`(`asc` + 元信息),但**编辑器这一轮按要求没动**:它读的、写的、
> 存的还是老格式(第一行 `// name:` + 地图的 txt)。后果有三条:
>
> 1. 它写出来的 `levels/<关卡名>.txt` **引擎照样读得进来**(老格式一直认),但它
>    **不会进 `levels/*.json`、也不会被 `node tools/sync_levels.mjs` 打包**;
>    `levels/` 里出现这种 txt 时,sync 和自检都会**提醒一句**。
> 2. 「保存到游戏」往浏览器关卡池里记的那份覆盖照样立刻生效(按 `R` 重构塔就能抽到),
>    只是它住在 `localStorage` 里 —— 换个浏览器 / 清掉数据就没了。
> 3. 编辑器"新层名字撞上内置关卡"那道拦截**这轮失效了**:以前内置层靠关卡名认人,
>    现在它们没有名字、只有固定 id,编辑器写的又是 `floor02.txt` —— 盖不掉
>    `levels/floor02.json`,但会往浏览器关卡池里写一条 id 为 `floor02` 的覆盖。
>    下一轮把编辑器接到新格式时要改成"按 id 拦撞车";编辑器自检里那几条已经按
>    这个新行为改写了(不再是"会拦住")。

### 地物调色板是"活的"

调色板里的东西**不是写死的**,全部从引擎的字符表推出来:

| 调色板里的分组 | 从哪来 | 现在有什么 |
|---|---|---|
| 空气(橡皮) | `level.js` 的 `EMPTY_CHARS` | `+` |
| 地块 | `level.js` 的 `TILE_IMAGES` | 草地 `^` 泥土 `_` 砖块 `~` 石块 `=` 云板 `-`(单向) |
| 起点 | `level.js` 的 `SPAWN_CHARS` | `P` |
| 地物 | `entities/` 的 `BY_LETTER` 注册表 | 出口 `G`、弹簧板 `S`、触之即散 `x`、浮石 `y` |

所以**以后往引擎里加什么,编辑器里就自动多一个笔刷**,不用改编辑器一行代码:
加一种地块 → 调色板多一格;注册一个新实体(`RA.register`)→ 调色板多一格,
连图标都会自动生成(实体可以自己写 `drawIcon(ctx, x, y, size)` 画得好看点,
不写就用默认的"带字符的方块")。自检里专门有一条:临时往引擎里塞一种新地块和一个新实体,
调色板必须自动多出这两个笔刷。

### 工具

| 工具 | 键 | 干什么 |
|---|---|---|
| 画笔 | `B` | 按住左键拖动,连续画;笔刷 1~9 格(3×3、5×5…) |
| 橡皮 | `E` | 擦成空气 |
| 矩形 | `R` | 拖一个框,松手整块填满 |
| 油漆桶 | `F` | 点一下,把连成一片的同种地物换掉 |
| 吸管 | `K` | 点一下取走那格的地物 |

视图:**右键 / 中键拖动平移**(或者按住 `Space` 用左键拖),**滚轮缩放**(以鼠标为中心),
方向键平移,「适应窗口」一键缩放到刚好放得下。撤销 `Ctrl+Z`、重做 `Ctrl+Shift+Z`
(一整笔拖动 = 一步撤销)。

### 大小不限(高度完全不设上限)

* 尺寸可以直接填(宽 / 高):**高度没有任何上限** —— 向上爬的塔,想画多高画多高,
  几万行、几十万行都行(单边只给宽度留了 `config.js` 里的 `EDITOR_MAX_COLS` = 600 格,
  再宽就不是竖井是壁纸了;高度那个参数 `EDITOR_MAX_ROWS` 默认 `0` = 不限)。
* 也可以**画到边界外让它自己长大**(默认开着,可以关)。自动扩展时视口会跟着补偿,
  画面不会跳;往左上长也一样。
* 大地图缩到很小的时候,地块自动改用近似色画(不然一次要画几千张图)。
* 视图开关:**网格**、**显示地物(P / G / S)**、**自动扩展**。地物关掉之后,
  画布上只剩地形,方便看清结构。
* 右边还有「尺寸」和「天空」:尺寸就是多少格(高度不限),天空决定这一层用哪张背景
  (不选 = 随层数循环)。

### 云板(`-`):单向平台

`-` 是**云板**:从下面往上跳能直接穿过去,从上面掉下来会被接住,横向也能穿过去
(它不算墙,也不会顶头)。用来做"一路往上跳的踏脚石"特别顺手 ——
爬塔里那种"看着够不着、其实能穿上去"的层,靠它就能做出来。

* **不算实心**:`RA.SOLID_CHARS`(实心地块)里没有它,所以横向 / 向上都不挡人;
  它在 `RA.ONEWAY_CHARS` 里,碰撞时只在"往下落"这一种情况下才接人。
* **能站、能当落脚点**:`level.surfaces()` 和可达性分析都把它当正常平台,
  出口 / 起点自动落地时也会落到它上面。
* **不能从上面钻下去**:按"下"不会掉下去(和很多游戏不一样,这里就是穿不过去的)。
* 编辑器里的调色板自动就有这个笔刷(调色板是从 `TILE_IMAGES` 推导的)。

### 会变的机关(`x` 触之即散 / `y` 浮石)

这两样都是 **1×1、带碰撞体积** 的地物(写法见 `js/entities/ghost.js` / `blink.js`),
在编辑器左边的调色板里直接能画。它们"算不算实心"是每帧变的 —— 引擎里
`Level._hitTiles()` 会把 `solidAt(r,c)` 返回 true 的地物当成一块砖:横向挡人、能站上去、
从下面会顶头。

| 字符 | 名字 | 体积 | 行为 |
|---|---|---|---|
| `x` | 触之即散 | 1×1 实心 | 玩家**从任何方向**碰到它的那一瞬间就开始散(0.12 秒),散完这一局**不再出现** —— 当一次性的墙 / 只能踩一次的台阶用 |
| `y` | 浮石 | 1×1 实心 | 玩家**只要踩到它(脚碰到顶面)它立刻消失**(0.12 秒收拢动画),过 1.6 秒再回来;回来之前先看那格空不空,**里面有人就再等一个周期**(不会把人卡进石头里) |

时序都在 `js/config.js` 里(`GHOST_FADE` / `BLINK_GONE`),
想调手感改那儿就行。浮石消失期间只留一圈虚影,让你知道它还会回来。

> 两个注意点:
> 1. 它们属于"会变的机关",`js/reach.js` 的**静态可达性分析不查实体** ——
>    一层的进出口别只靠它们连着,画完自己按 `P` 试玩一遍。
> 2. 从下面顶它们的时候,玩家会被顶到方块下边缘往里 1px(而不是正好贴着),
>    这样"碰到"才判得出来 —— 视觉上看不出来,但碰撞判定稳。

### 起点和出口是硬要求

检查面板一直在盯着,以下情况会直接**拦住试玩 / 保存到游戏 / 下载**:

* 没有 `P`(出生点)→ 报错;`P` 多于一个 → 报错(引擎只认第一个)
* 没有 `G`(出口)→ 报错;`G` 多于一个 → 提醒(只有第一个算数)
* `P` 下面整列都没有地面 → 报错(角色会一直往下掉)
* 有不认识的字符 → 报错并指到具体行列
* 提醒级:`G` 悬在半空、`G` 不在 `P` 上面、弹簧板 `S` 没贴着地面

### 名字:新建的必填,老关卡沿用

> 这一节讲的全是**老格式**(第一行 `// name:` + 地图的 txt)—— 编辑器这轮还是这一套。
> 新格式里关卡已经**没有名字**了,只有 `id`(见上面「怎么设计楼层」);等下一轮把编辑器
> 接到新格式,这里就会改成"名字就是 id"。

* **新建一层会自动起名**:新楼层 1、新楼层 2……(跳过内置关卡和浏览器里已经存过的
  那些名字,所以不会撞名 —— 内置关卡现在用的名字就是它们的 id `floor01`…`floor12`)。
  想改就改中间那个输入框。
* **新建的层「保存到游戏」必须有名字**:名字同时是 txt 的文件名,没名字就没法落盘 ——
  把名字清空的话,检查面板会报一条红字,「下载 txt / 保存到游戏 / 复制」会被拦住,
  并把光标送回输入框。
* **从关卡池 / txt 打开的老关卡不用管名字**:它沿用它原来的名字和文件名。
  就算你不小心把输入框清空了,保存时会自动从原来那份文本里把名字找回来
  (`floor01.txt` 还是 `floor01.txt`,不会在 `levels/` 里多出一份)。
* 名字存在 `// name:` 注释里(第一行),**同时也是 txt 的文件名**:

  ```
  // name: 云梯          ← 关卡名(也是 云梯.txt 这个文件名)
  +++++++++++++++
  +P+++++++++++++
  ```

  名字里不能做文件名的字符(`\ / : * ? " < > |` 和空格)会被换成 `_`。
  从关卡池 / txt 打开的层则**沿用它原来的文件名**(`floor01.txt` 还是 `floor01.txt`),
  改名字只改注释里的名字 —— 不会在 `levels/` 里多出一份。

### 保存到游戏(写文件 + 关卡池,一次做两件)

点<b>「保存到游戏」</b>会同时:

1. **写一份老格式 txt 进 `levels/`**(文件夹内容)—— 文件名就是关卡名,
   从关卡池/txt 打开的层按原文件名存回去(改显示名只改 `// name:`,不会多出一份)。
   ⚠ **这一轮编辑器还没接新格式**:它写出来的就是这种 txt —— 引擎读得进来,但它
   **不会变成 `levels/<id>.json`,也不会被 `node tools/sync_levels.mjs` 打包**;
   `levels/` 里出现这种 txt 时,sync 和自检会提醒一句。想让一层真正进项目,得手写 /
   改一个 `levels/<id>.json`(见上面「怎么设计楼层」),或者等下一轮编辑器接上新格式;
2. **把浏览器里的关卡池也换成这一份**(关卡内容)—— 记在
   `localStorage` 的 `reverse_abyss.overrides` 里,key 就是关卡池 id(`floor01` / `云梯`)。

所以回 `index.html` 之后:

| 你存的是 | 游戏里会怎样 |
|---|---|
| **新的一份**(或者不在塔里的老关卡) | 它马上进关卡池(不用刷新页面)—— 在设置里按 `R` **重构塔**就有概率被抽到;塔里没抽到就再重构几次,或者把塔高调大一点 |
| **塔里本来就有的那一层**(`floor01` 这种) | 关卡池里那一层的**同一个 id** 换成了新文本,刷新页面后塔里那一层就变成你改过的样子 |

> 一次重构是"重新抽一次层":池子里模板越多,某一层被抽中的概率越小 ——
> 想马上看到自己刚存的层,就多按几次 `R`,或者把塔高(↑↓)调高一点。

第 2 步还顺手解决了一个老坑:**双击 `index.html`(file://)时浏览器读不了本地文件**,
关卡池只能用 `levels/levels.js` 那份内嵌副本 —— 你改了 `levels/floor01.json` 但没跑
`node tools/sync_levels.mjs`,游戏里就还是旧地图。有了这份覆盖,存完**刷新页面就是新地图**,
不用等 node。优先级很清楚:**能读到文件就以文件为准**(http 打开时会 fetch
`levels/<id>.json`;没有 json 就退回读老格式的 `levels/<id>.txt`),
这份覆盖只在读不到文件的时候生效。

而且**同一个 id / 关卡名在浏览器里只会算一层**:改过名之后重新保存,旧名字那份(不管是
`overrides` 还是游戏里「导入关卡」留下的 `custom_` 副本)会被顺手清掉,塔结构表里
不会冒出两个同名的层。(`custom_<名字>` 这种 id 在游戏里显示的时候会把 `custom_` 前缀去掉,
所以「导入关卡」进来的自定义层看到的就是它的名字。)

> 只想导出一份文件、不动游戏 →「下载 txt」(它会明确告诉你"游戏里的关卡池没变")。

### 关卡存哪、怎么清

| 存在哪 | 谁写的 | 怎么清 |
|---|---|---|
| `levels/<id>.json`(关卡源头) | 手写 / 复制 `_template.json` 改一个 | 删文件,再跑 `node tools/sync_levels.mjs` |
| `levels/<关卡名>.txt`(老格式) | 编辑器「保存到游戏」/「下载 txt」手动放进来(老文件早就删光了) | 直接删文件 —— 注意它本来就**不进** `levels/*.json`、也不打包,sync / 自检只会提醒它还在 |
| 浏览器 `localStorage`(键 `reverse_abyss.customLevels`)| 游戏设置面板「导入关卡」留下的层(下拉框里 `★` 开头) | 编辑器里没有清理入口了,用控制台:`RA.LevelPack.removeCustom(RA.LevelPack.customId('名字'))` |
| 浏览器 `localStorage`(键 `reverse_abyss.overrides`)| 「保存到游戏」顺手记下的"同一层的新文本"(下拉框里 `✎` 开头;读不到文件时优先) | 控制台:`RA.LevelPack.removeOverride('floor01')`;删掉后游戏回到 json / 内嵌那份 |

> 所以如果你存过几层却"不知道存哪了",多半就在浏览器 `localStorage` 里 ——
> 打开 `editor.html`,看关卡下拉框里 `✎` / `★` 开头的那几项。
> 正常情况下不用手动清:编辑器保存时会自动清掉同名的旧副本(见上一节)。

### 最上面那三个去处

1. **试玩(P)** —— **开一个新标签页**(`play.html`),用真正的引擎玩你画的那一层,
   铺满窗口、真物理真手感,走到出口就算通。玩完之后页面上给两个选择:
   **重新开始**(同一份文本从头再玩一遍)、**回编辑器**(关掉试玩页,回到你原来那一页接着改;
   中途按 `Esc` 也能叫出这个面板,那时还会多一个「继续玩」)。
   浏览器不许网页关自己开的标签页时会退一步:把编辑器那一页拉到前面,并提示你手动关掉。
   > 为什么不在编辑器页里直接玩:那一页是原生控件 + 地图画布,塞不下全屏游戏;
   > 新标签页还有个好处 —— 关掉它就等于"回编辑器",你原来那页的撤销栈、视角、光标一点没动。
2. **下载 txt** —— 文件名就是关卡名(老格式)。文件是出来了,但**游戏里的关卡池没变**,
   而且这种 txt **不会进 `levels/*.json`、也不会被 `node tools/sync_levels.mjs` 打包** ——
   想让它真进项目,得把地图抄进一个 `levels/<id>.json`(见上面「怎么设计楼层」),
   或者等下一轮编辑器接上新格式。
3. **保存到游戏** —— 见上面那节:写进 `levels/`(老格式 txt)+ 换掉浏览器里的关卡池。
   浏览器不许网页自己往磁盘写,所以要**授权一次**:
   点「选择 levels 文件夹…」,在弹出来的对话框里选中项目的 `levels/`
   (Chrome / Edge 支持这个 API;句柄记在本机 IndexedDB 里,下次打开编辑器还在,
   也能点「忘掉」)。不支持这个 API 的浏览器(Firefox / Safari)会退回「下载 txt」。
   勾上「改完自动写入(1.5 秒)」的话,每次停下笔 1.5 秒就会自动落盘。

   `打开 txt…` 也能反过来打开任何一份老格式的 txt(编辑器自己存出去的那种,或者别处
   拿来的),改一改再存回去,所以它也能当"改关卡"的工具使。
   下拉框里的 `打开选中的` 拿的是**游戏现在真正在用的那份**:
   `★` 的开浏览器里存的那份,`✎` 的开覆盖过的那份 —— 不会像以前那样打开旧的内嵌数据。

### 「← 回游戏」:有改动会先问一句

编辑器左上角那个 `← 回游戏` 不再是"直接走人":

* **这一层没改过** → 直接回游戏(能关掉标签页就关,关不掉就跳回 `index.html`);
* **有没保存的改动** → 先弹一句确认:**"要先把这一层保存到游戏吗?"**
  * 选 `是` = 走一遍「保存到游戏」:新层还没起名会先让你起名;写不进去就留在编辑器接着改;
    **存成了才离页**;
  * 选 `否` = 不保存,直接回游戏。

> 用的是浏览器自带的确认框(故意的):一句话就能问清楚,而且你点"是"的这次手势
> 还能接着用于「选择 levels 文件夹…」的授权弹窗 —— 换成自绘弹窗反而会被浏览器拦。

> 编辑器里一切都是原生 HTML 控件(输入框 / 下拉框 / 复选框),所以中文关卡名
> 能用输入法打;画布只负责画地图。所有这些按钮的 id 都有自检盯着:
> `editor.js` 里用到的每个 id 必须在 `editor.html` 里存在,引用的脚本路径也要对得上;
> `play.html` 的脚本清单(引擎 + `js/playtest.js`)也在自检里对着。

> 想回顾"为什么长成现在这样":看 **`log.txt`** —— 每一轮改了什么、踩了什么坑、
> 还剩什么问题都记在那儿(README 只讲现状和怎么用)。

## 贴图:四块地方,想换就换

所有贴图都是 `assets/` 下**独立的 PNG 文件**,游戏启动时按文件名读进来:

| 放哪 | 是什么 | 尺寸 |
|------|--------|------|
| `assets/tiles/` | 关卡地块:草地 `grass_top` / 泥土 `dirt` / 砖块 `brick` / 石块 `stone` / 云板 `cloud` | **随便多大**(现在是 16×16 的像素画;画的时候缩放到一格,见下面) |
| `assets/entities/` | 实体:`spring.png` 弹簧板 `S` / `goal.png` 出口光柱 `G` / `blink.png` 浮石 `y` | 弹簧板和浮石 45×45;出口 `GOAL_WIDTH`×`GOAL_HEIGHT`(34×96,就是判定盒那么大) |
| `assets/sky/` | 天空背景 `sky1.png` ~ `sky8.png` | 960×540(按比例铺满) |
| `assets/ui/` | 界面背景 `title.png`(开局界面 + 退出后的告别页) | 960×540 |

**地块贴图的尺寸不用跟格子一样**(第七轮改的):`assets/tiles/` 里现在是 `textures/block`
那套 16×16 的像素画,游戏和编辑器画的时候都统一**缩放到一格**(`config.TS` = 45px),
规则只有一处 —— `js/level.js` 的 `drawTile()`。对应关系:

| 游戏里的地块 | 用的贴图 | 是什么 |
|---|---|---|
| `grass_top.png`(草地 `^`) | `grass_block_side.png` | 上面一条草、下面泥土的草方块侧面 |
| `dirt.png`(泥土 `_`) | `dirt.png` | 泥土 |
| `brick.png`(砖块 `~`) | `bricks.png` | 红砖 |
| `stone.png`(石块 `=`) | `stone.png` | 石头 |
| `cloud.png`(云板 `-`) | `snow.png` | 雪(当"薄云板"用:只画贴图上面 29%,所以看着是薄薄一条) |

* 源图比一格**小**(像素画)→ 放大时**关掉平滑**,保持硬边,不会糊成一片;
* 源图比一格**大**(比如 128×128)→ 缩小,保留平滑,不会出现摩尔纹;
* 所以换 32×32 / 64×64 甚至 128×128 的贴图包都不用改代码,替换这 5 个 PNG 就行(文件名别改)。
* 云板是"薄平台":`level.js` 的 `TILE_PLATE` 写着它只画上面多高 —— 改那个数就能让云板更厚 / 更薄,
  游戏和编辑器会一起变(两边都走 `RA.drawTile()`)。

`assets/entities/` 这三张是第六轮从"在 `js/entities/*.js` 里现画"挪过来的:画法一模一样,
只是挪进了统一的光栅器 / PNG 管线,好处是换风格用画图软件直接改就行。
**动效还在,而且是画那张 PNG 时候的动**:弹簧板踩下去整块贴图下沉 `squash*7` px;
出口光柱靠 `globalAlpha` 在 0.75~1 之间呼吸(它下面那个底座和「上一层」那行字还是代码画的);
浮石消失时把同一张贴图按收拢进度缩放。三张图都留着"现画"的兜底。

**天空怎么用**:默认**随层数循环** —— 第 1 层 sky1、第 2 层 sky2……第 8 层 sky8,
第 9 层又回到 sky1(所以越往上爬天色越亮)。想让某一层固定用某一张,
在那个关卡的 json 里把 `sky` 写成 1~8 就行:

```json
{
  "id": "floor13",
  "sky": 5,
  "asc": ["...地图..."]
}
```

关卡编辑器右边也有个「天空」下拉框(它现在写的是老格式的 `// sky: N` 注释行),
`node tools/check_levels.mjs` 和自检都会盯着这个值合不合法(超出 1~8 会被忽略并提醒)。

**重新生成**:`node tools/build_assets.mjs` —— 它自带一个很小的软件光栅器 + PNG 编码器,
零依赖,在命令行里就能把**实体 / 天空 / 界面**那几张重画一遍。改了画法记得重跑:
自检里有一条会拿"现在会画出来的内容"和磁盘上的 PNG **逐字节**对比,忘了重跑会被测出来。

**地块不在它的管辖范围内** —— `assets/tiles/` 那 5 张是贴图包里的图,跑这个脚本不会覆盖它们。
想回到以前那套"代码现画"的地块(45×45 带描边的方块),用后路:

```bash
node tools/build_assets.mjs --restore-tiles     # 只会重画 assets/tiles/ 这 5 张
```

把 PNG 删了/改了也不会崩 —— 每个素材都有一份"现画"的兜底(风格和生成的图一致),
地块也不例外(`js/assets.js` 里那 5 个 `tileXxx()`)。

## 怎么扩展

### 加一个新东西(金币、敌人、传送门……)

1. 在 `js/entities/` 里新建一个文件,比如 `coin.js`:

```js
(function (RA) {
  'use strict';
  class Coin extends RA.Entity {
    update(dt, game) {                      // 每帧逻辑(可省)
      if (!this.alive) return;
      var p = game.player;
      if (RA.overlap(p.x, p.y, p.w, p.h, this.x, this.y, this.w, this.h)) {
        this.alive = false;                 // 碰到就消失
        game.snd.play('jump');
      }
    }
    draw(ctx, cam, assets) {                // 画自己(可省)
      if (!this.alive) return;
      RA.circle(ctx, this.cx - cam.ox, this.cy - cam.oy, 10, [255, 205, 110]);
    }
  }
  Coin.letter = 'c';                        // 地图里写 c 就摆一个
  RA.register(Coin);
  RA.Coin = Coin;
})(globalThis.RA = globalThis.RA || {});
```

2. 在 `index.html` 的 `<script>` 列表里加一行、`tools/loader.mjs` 的 `ENGINE` 里加一行
3. 关卡地图里写 `c`

**引擎代码一行都不用改。** 现成的例子就是 `js/entities/spring.js`;
想要"有碰撞体积、会挡人的地物"就看 `js/entities/ghost.js` / `blink.js` ——
它们只多写了一个方法:

```js
solidAt(r, c) {          // 这一格现在挡不挡人?(默认不挡)
  return r === this.row && c === this.col;   // 1×1:占着自己那一格
}
```

返回 true 的格子会被 `Level._hitTiles()` 当成一块**实心砖**:横向挡人、能站上去、
从下面顶头。状态一变就返回 false,碰撞立刻跟着变(浮石消失 / 碎影散掉就是这么做的)。
注意 `js/reach.js` 的静态可达性分析**不查实体**,靠它们上下的层要自己试玩确认。

### 加一种怪物(要带参数的东西)

一个地图字符只能写一个字,带不了"速度 120、往左飞、打两下才没"这种参数。所以这类东西
不做字符,走关卡 json 的 `objects[]`。三件事:

1. **在 `js/monsters.js` 里登记参数**:`MONSTERS` 加一条,写清楚它有哪些参数、默认值多少
   (`fireball` 现在就是一条参数空着的样板)。`RA.Monsters.get / ids / defaults / paramsOf`
   读的就是这张表,`paramsOf` 会把关卡里写的参数盖在默认值上。
2. **在 `js/entities/` 里写实体类**,类上写一行 `Fireball.type = 'fireball'`
   (注意**不要**写 `letter` —— 它不该出现在编辑器调色板里)。构造签名是
   `(level, col, row, params)`。
3. **在关卡 json 里摆**:
   ```json
   "objects": [
     { "type": "fireball", "col": 3, "row": 5, "params": {} }
   ]
   ```

引擎一行都不用改:注册完 `RA.BY_TYPE` 里就有它,`level.js` 的 `_buildObjects` 读
`objects[]` 时按 `type` 找类、生成实体;没登记过的 type 只留数据、不报错(所以可以先把
参数写进关卡,等行为补上了自动就生效)。**编辑器这一轮还摆不了 objects**(它还是老格式),
要摆得手改 json。

### 加一种新地块(沙地、铁板……)

> 想加的是"单向平台"那种只挡一个方向的,已经有现成的 `-` 云板了;
> 想再加一种,写进 `level.js` 的 `ONEWAY_CHARS` 字符串就行
> (`SOLID_CHARS` 会自动把它排除掉),剩下的步骤和下面一样。

`js/level.js` 顶部的 `TILE_IMAGES` 加一行:

```js
var TILE_IMAGES = {
  '^': ['tiles/grass_top', '草地'],
  '_': ['tiles/dirt', '泥土'],
  '~': ['tiles/brick', '砖块'],
  '=': ['tiles/stone', '石块'],
  '%': ['tiles/sand', '沙地'],        // ← 加这一行
};
```

再往 `assets/tiles/` 放一张 `sand.png`(多大都行,画的时候会缩放到一格),
地图里就能写 `%` 了。想让它缺图时也有个兜底,就在 `js/assets.js` 的 `BUILDERS` 里加一个画沙地的函数
(照抄 `tileDirt()` 改配色即可)。实心判定、绘制、检查工具的图例、**关卡编辑器的调色板**
全都是**从这张表自动推出来的** —— 加完刷新编辑器,`%` 的笔刷就在那儿了。
想做非实心的地块(掉下去会死的岩浆),那要动 `js/level.js` 的碰撞,不只加图。

### 换角色手感 / 加一个新角色

手感数值分两层:`js/config.js` 里是全局默认,`Player` 类上的静态值才是这个角色真正用的。
想给某个角色单独调,就在类上覆盖(甚至 `player.MAX_VX = 500` 只改这一个实例)。
碰撞盒 `W/H`、贴图表 `SPRITES`、脚底对齐 `FEET_ANCHOR` 也都是数据。

### 换素材 / 加音效

* 素材:直接替换 `assets/` 下对应名字的 PNG(哪张对应什么,见上面「贴图:四块地方」那张表;
  `js/assets.js` 的 `FILES` 是唯一的对照表)。地块尺寸随意,画的时候会缩放到一格;
  实体 / 天空 / 界面这三类是代码画的,想彻底重画就跑 `node tools/build_assets.mjs`。
* 音效:在 `js/audio.js` 的 `SPECS` 里照着写一行(时长、起止频率、音量、波形、衰减),
  再在代码里 `game.snd.play('你起的名字')`。想做一段小旋律就用 `_chime()` 那种写法。

### 换数值 / 调手感

全在 `js/config.js`。常用的几张:

| 变量 | 含义 |
|------|------|
| `WIDTH` `HEIGHT` `FPS` | 画布内部尺寸与帧率(窗口由 CSS 等比缩放) |
| `MAX_VX` / `AIR_MAX_VX` | 地面/空中最大速度 |
| `JUMP_VEL` / `GRAVITY` | 跳多高 / 重力多大 |
| `JUMP_COUNT` | 一次滞空能跳几次(默认 2 = 开二段跳) |
| `LEDGE_ASSIST` | 落脚容错:离墙顶多近算"只差一点点"(0 = 关掉) |
| `GOAL_WIDTH` / `GOAL_HEIGHT` | 出口判定盒的宽 / 高 |
| `SPRING_VEL` | 弹簧板弹多高 |
| `TOWER_FLOORS` `TOWER_FLOORS_MIN/MAX` | 默认塔高 / 允许的塔高范围 |
| `TOWER_NO_REPEAT_GAP` | 相邻几层内不重复用同一个模板 |
| `MIRROR_DEFAULT` | 重构时是否允许镜像 |
| `FLOOR_METERS` | 一层算多少米(纯显示) |
| `CLIMB_TIME` | 爬升过渡动画时长 |
| `EDITOR_MAX_COLS` / `EDITOR_MAX_ROWS` | 编辑器里的宽度上限 / 高度上限(**0 = 高度不限**) |

物理参数单位都是秒,与帧率无关。

## 自动测试

```bash
node tools/test_all.mjs             # 引擎 + 编辑器,一条命令跑完(含逐跳物理模拟)
node tools/test_all.mjs --fast      # 跳过模拟,快
node tools/test_engine.mjs          # 只测引擎
node tools/test_editor.mjs          # 只测编辑器
```

**引擎自检**(577 项)检查:

1. **关卡数据同步 + 体检** —— `levels.js` 是不是和 `levels/*.json` 一致(改了忘同步会在这报)、
   `levels.js` 里没有已经删掉的关卡;每个关卡的数据本身也过一遍:数据里的 `id` 和池子里的键
   一致、难度在 1~4、`verified` 是布尔、`size` 和 asc 读出来的大小对得上、`objects` 是数组、
   `asc` 是一行一项且行数和 `size.rows` 一致、`asc` 里没有注释残留、**数据里没有名字字段**
   (名字已经去掉了)。
   > `levels/` 里要是还留着老格式 txt(编辑器这轮写的),这里**只提醒一句**,不算失败 ——
   > 引擎读得进来,但那不是关卡源头、也不会被 sync 打包。
2. **关卡数据怎么读** —— 难度 1~4 档(超范围夹回来、写字符串也认、没写就是 1 档)、
   `verified` 没写就当验过、`size` 和 asc 对不上会提醒一句**而且以 asc 为准**、
   `objects` 读进 `level.objects`(还没实现的类型只留数据不报错;在实体类上写了 `type`
   再注册就真的生成实体);三种写法都认:**json 对象 / JSON 字符串(导入 .json 文件)/
   老格式纯地图文本**;外加**怪物参数表**:`js/monsters.js` 装上了、表里有 `fireball`、
   它的参数先空着、没登记的类型返回 `null`;
3. **http 实时读关卡** —— http 打开时会 `fetch` `levels/<id>.json`,磁盘上那份盖过内嵌那份
   (尺寸 / `verified` 都跟着变);那一层没有 json 就**退回读老格式 `levels/<id>.txt`**;
   两种都没有时保留内嵌那份 —— 不报错、不空池子;
4. **物理** —— 在**每一层**上都跑一遍:站立不下陷、静止不闪帧、跳起落地、二段跳更高且
   只补一次、翻滚最多一圈且落地归位、落脚容错(以及关掉就上不去)、高台站立、半空起跳镜头不抖、
   出口判定;
   > 二段跳那几条量的是**手感**,所以量的时候会把这一层的碰撞网格临时换成"全空气"
   > (起跳点还是这一层的出生点)。不然一层只要天花板低一点,"跳不高"就会被记到引擎头上 ——
   > 而那是关卡的事,不是引擎的事。
5. **弹簧板** —— 弹起高度、补满二段跳;
5b. **会变的机关** —— 合成两层单独验:`x`(触之即散)有碰撞体积、往它走会被挡住、
   碰到就开始消失、消失后能穿过去、散完同一局不再出现、**从下面顶也算碰到**;
   `y`(浮石)算实心、能站上去、踩到那一刻就消失、消失时不挡人、踩在上面的人会掉下去、
   玩家走开后过一段会回来、**格子里有人时不重现、再等一个周期**;
6. **主循环** —— 掉出世界回起点并记一次坠落、碰到出口进入过渡、过渡完站在第 2 层;
7. **关卡切换的渐入渐出** —— 单独一段盯着:刚进过渡时旧层还全亮、新层还没出现、还没压暗;
   两层各在自己的镜头上、`panY` 一直是 0(**不再把整层上下推**);第一帧只画旧层;
   跑到一半旧层几乎淡没、新层还没亮、**中间那层暗场最浓**,而且同一帧里旧层新层都在淡;
   快结束时新层基本全亮、旧层已经没了;过渡结束站进新楼层、镜头偏移归零、透明度回到 1;

## 下一步可以做什么

* **编辑器再进一步**:框选移动 / 复制粘贴、把某一块存成"预制件"、图层(背景 / 机关 / 装饰)、
  直接在编辑器里切换地块皮肤。
* **坠落惩罚**:现在掉下去只是回本层起点;想让"掉一层"就改 `game.js` 里
  `updatePlay()` 那三行(把上一层的 Level 留着、重生点换成上一层的出生点)。
* **层内难度变体**:`tower.js` 抽层时除了镜像,还可以按种子删掉/加高几块平台,
  让"结构不固定"更彻底。
* **存档**:把种子 + 已爬层数写进 `localStorage`,刷新接着爬
  (自定义关卡已经这么存了,`levelpack.js` 里有现成的读写函数)。
* **触屏操作**:`input.js` 已经把触点和鼠标按键都接好了;再补两个虚拟按钮就能手机上玩。
* **多层同屏**:把上下两层拼进同一个世界(`fromText` 拼行)就能做成"看得见塔身"的连续攀爬。
* **更多机关**:金币、会动的平台、会碎的砖、风区 —— 全部照 `spring.js` 的路子加字符,
  加完编辑器里自动就有笔刷。
* **BGM / 通关演出**:`audio.js` 加一段循环音、`game.js` 的 `victory` 状态加个演出。

## 已知限制

* **双击打开(file://)时读不到本地文件**(浏览器的安全限制),所以关卡数据走的是
  `levels/levels.js` 这份内嵌副本:改完 `levels/*.json` 要跑 `node tools/sync_levels.mjs`。
  用 `python -m http.server` 打开就没这个问题,运行时会直接 `fetch` `levels/<id>.json`
  (那一层没有 json 就退回读老格式的 `levels/<id>.txt`)。
* **编辑器这一轮还没接新格式**:它读写的仍是老格式 `// name:` + 地图的 txt ——
  引擎**照样读得进来**,但那份 txt **不会进 `levels/*.json`、也不会被 `sync_levels.mjs`
  打包**(`levels/` 里出现这种 txt 时,sync 和自检会提醒一句)。所以「保存到游戏」写出来的
  文件只是"引擎能读的一份文本",不是关卡源头;要用它就得把地图抄进 `levels/<id>.json`。
  另外它"新层名字撞上内置关卡"那道拦截这轮**失效了**(内置层已经没有名字,只有 id):
  它写的是 `floor02.txt`,盖不掉 `levels/floor02.json`,但会往浏览器关卡池里写一条 id 为
  `floor02` 的覆盖 —— 下一轮接新格式时改成"按 id 拦撞车"(见"已知问题 6")。
* **双击打开(file://)时关卡池也读不到 txt**,只能读 `levels/levels.js` 的内嵌副本,
  加上浏览器里那份 `localStorage` 覆盖 —— 编辑器「保存到游戏」写出来的 txt(还有它顺手记的
  覆盖)是引擎能用的,但那份 txt 本身不会变成关卡源头。
* 编辑器「保存到游戏」要浏览器支持 File System Access API(Chrome / Edge 有;
  句柄存在 IndexedDB 里);不支持的浏览器(Firefox / Safari)会退回「下载 txt」。
  少数浏览器在 `file://` 下会禁掉 `localStorage`,那浏览器里那份"关卡池覆盖"就只在本次有效 ——
  但**写进 `levels/` 的那份 txt 是真的**,引擎(以及导入关卡)读得进来,
  只是别指望 `sync_levels.mjs` 会把它打进 `levels.js`。
* 网页没法**未经授权**就写磁盘,所以「保存到游戏」第一次一定要你选一次 levels 文件夹;
  之后 (同一个浏览器 + 同一个站点) 会记住。
* **手改 `levels/*.json` 之后,file:// 打开的游戏不会自动看到** —— 它只能读内嵌的
  `levels/levels.js`。要么跑一次 `node tools/sync_levels.mjs`,要么用编辑器
  「保存到游戏」(它会把浏览器里那份覆盖也一起更新,刷新就有效果),要么用
  `python -m http.server` 之类的 http 方式打开(运行时会实时 fetch `levels/<id>.json`)。
* 贴图是**文件**(不是程序画的),所以直接用画图软件改 `assets/` 下的 PNG 就行;
  改完不用重启,刷新页面即可(想彻底重画就跑 `node tools/build_assets.mjs`)。
* 第一次按键之前浏览器不许出声,所以音效要等你按一下键 / 点一下鼠标才会出现。
* 玩法只做了键盘(菜单和编辑器可以用鼠标,触屏只能点按钮)。
* 每次"重构"都是重新抽层,不保存历史;想复现就靠种子。
